Sentry on a clean ReAct/LongContext actor: first bounded hypothesis, 2026-10-18

Research scope
Directly improve author Sentry, not the previous layered SCAR actor. The full
persistent-blocker proposal remains a hypothesis. First test one observed
failure in the information supplied to its decisions: recent-window absence
can be confused with absence from the actual interaction history.
The existing SCAR-prompt/Sentry Mark development run at cycle62 calls prior
copper acquisition and sword crafting fabricated, although actual cycles45/47
confirm them. Its same diagnosis also contains a valid current storage error;
do not call the whole intervention unnecessary. Across two selected old runs,
Sentry reports3/25 and7/26 verified recoveries. Its verifier labels are not an
independent metric, and these runs do not use the new clean actor.

Frozen v1 change
An append-only ledger contains literal executed actions and public subsequent
observations; no actor reasoning, private state, scores or invented facts.
A deterministic lexical retrieval exposes at most6 older excerpts, at most1400
characters each, outside the recent5-cycle window. At most2 records per exact
command. Historical views are explicitly dated and are not current inventory.
Absence from a bounded excerpt is not evidence of nonoccurrence. Keep valid
present failures even when a separate historical allegation is corrected.
The same additional context is available to the author detector and verifier.
No extra LLM call, action override, new action family, hand-written game entity,
modified Sentry taxonomy, retrieval of playbook rules, or H=10 change is added.
This is an evidence-access ablation, not a completed persistent-repair policy.

Actor and controls
Reproduce AgentOdyssey LongContext prompt/memory formatting and default ReAct
system instruction, with shared audited JSON transport. No SCAR notebook,
task parser, causal search, action gate, or old repair policy is inherited.
Append author Sentry guidance to host conversation; retain it in normal history
as the integration supports. The whole playbook is never inserted. One clean
baseline, original Sentry, and Sentry+historical evidence use the SAME actor.
Actor DeepSeek-flash temperature.7 top_p.8 max1536, presence_penalty0; author
Sentry auxiliary temp0/max4096/default W5/H10. No thinking. JSON retry deviations
and all attempts are logged. Schema-valid semantic errors are not malformed
actions; accepted_by_environment remains unknown. No reward enters Sentry.

Evaluation fixed before results
First reproduce fixed-window diagnoses from all soft rescues in the two old
development logs (26+27), using cached original requests when exact. Inspect
the known erroneous historical allegation and whether the valid storage error
is retained. This diagnostic is not an independent game-performance measure.
Then run one fresh post-freeze draw each of remnant, mark and metropolis, with
base / original Sentry / evidence variant, maximum300 actual actions each.
No favorable-world selection; reset all memory before each game. This is a
small development pilot within familiar families, not a formal significance
test. No tuning or additional version based on its results in this batch.
Each world shares an initial private snapshot and a step-specific exact-request
cache. Separate worlds have separate caches. File locks prevent duplicate
paid concurrent calls. Record randomly drawn hash seed for consistent upstream
set iteration, not chosen environment seeds. Every action gets exact snapshot
replay verification; independently audit common action-prefix state equality.
Report all three endpoint scores, passes, score-vs-step landmarks, semantic
failures, Sentry interventions/verifications, actual cost and token increase.
Positive diagnosis accuracy alone does not establish recovery or score gain.
No additional large evaluation is justified without evidence of useful impact.
