Initial conditions and action randomness
  The nine evaluation_plan jobs were fixed before their worlds were drawn.
  Environment reset requests seed=None; each initial_receipt records the actual
  generated seed and initial snapshot/state hashes. No favorable-seed selection.
  PYTHONHASHSEED is separately drawn once per block and recorded in its manifest.
  It MUST be set before starting Python. Upstream rules construct RNG-choice
  arrays from sets, so restoring only environment RNG is insufficient.
  Each block runs all four arms in one process with separate world snapshots.
  Same-step identical API requests share a response only inside that block.
  This is common-random-number coupling, not independence between paired arms.
  Independent blocks use different caches and fresh initial states.
  Repetition index rotates arm order. Actor computation cannot modify world RNG:
  the environment is restored immediately before each step.

Invocation
  Work in the frozen source directory containing source_manifest.json.
  Supply the API key as a PRIVATE FILE path, never as a command argument value.
  Run, with each recorded job's PYTHONHASHSEED in the process environment:
    python -m scar_public.experiments.core_trial --root BLOCK_DIRECTORY \
      --game GAME --repeat REPETITION --steps 300 --key PRIVATE_KEY_FILE
  Default arms are prompt,checked,sentry,v16. See core_protocol.txt for decoding.
  For an exact rerun, retain the PRIVATE initial.pkl and API cache in the block.
  Existing result traces are checked for exact action/state-prefix equality.
  Recreating a seed alone is not guaranteed to recreate the historical state
  across Python/library versions. Raw environment snapshots are not actor input.

Analysis and no-API replay
  python -m scar_public.experiments.analyze_core_trial --root STUDY_DIRECTORY
  This refuses incomplete blocks and reports all nine paired differences.
  With a block's recorded PYTHONHASHSEED and the frozen source on PYTHONPATH:
    python replay_core_environment.py --block BLOCK_DIRECTORY
  Replay uses recorded commands, not model generation. It compares all public
  observations, before/after state digests, score updates and terminal flags.
  At checked overrides it also branches one step to the original LLM command
  from the exact pre-action state. These offline diagnostics use no API calls
  and are excluded from formal episode budgets. Immediate effects do not prove
  the value of a full alternative trajectory or the whole intervention policy.
  Runtime checks also require equal packets and LLM proposals before the first
  prompt/checked action divergence, and equal notebook states when actions agree.

Interpretation
  The main authority contrast includes the SAME notebook, planning computation,
  decision packet, LLM revision and decoding. Only the final action gate differs.
  The Sentry arm is the SAME prompt actor plus author Sentry's detection,
  retrieval, verification and playbook update. Empty playbook in every episode;
  public observations only. It uses the supported host-guidance integration,
  shared1536-token actor limit and default4096-token auxiliary limit, not the
  paper's384-token repair actor. This is an adaptation, not its paper benchmark.
  V16 is an internal prior SCAR reference, not a new external baseline.
  This evaluates the consolidated SCAR pipeline, not task persistence alone.

  Three new draws per familiar game family give a small independent evaluation.
  These are not unseen domains. A higher raw quest score is partial progress,
  not a higher main-task completion rate when every arm has zero completions.
  Exact sign-flip p-values rely on exchangeability/symmetry of paired differences
  under the null; the small within-family bootstrap interval is exploratory.
  The protocol's joint criterion was fixed before results; do not weaken it
  after observing outcomes or present its failure as proof of equivalence.
