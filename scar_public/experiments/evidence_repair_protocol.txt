Frozen prospective evaluation protocol, 2026-10-17

Question: Does scoped semantic evidence plus enabling-condition repair improve
real game progress over prompt-only facts and an exact contextual failure cache?

Run four V11 arms (none, prompt, cache, structured) on each of Remnant, Mark and
Metropolis. Each game gets a newly drawn default seed, no manually fixed seed.
All four arms share that game's initial physical snapshot and decoding settings.
These are fresh trajectories on existing templates, NOT independent game domains
or a formal multi-seed replication. Each arm stops at environment completion or
300 actions. Run one per cell in this development round. No old baseline reruns.

All modes collect the same type of actual craft observations, use the same local
planner and per-profile prospective cost gate. Different paths can acquire
different facts; no counterfactual facts are injected. None hides stored evidence;
prompt exposes applicable surviving joint rules only; cache rejects an exact
failed command in the same observed arrangement and guard epoch; structured
also filters planning, exposes enabling conditions and attempts a strong local
repair (six additional bounded searches maximum). This is a component-package
comparison; differences do not individually identify each new component's effect.

The guard adds public calendar/hour, level/attack/defense and explicit modifier
lines. This is conservative scoping, not learned temporal invariance. All actions
advance game time. Failure rejection remains a model-relative decision heuristic
in the real game, not a proven dominance relation over hidden time effects.

Primary: quest score and environment completion at the budget/end. Secondary:
failed craft attempts; verified-rule exclusions; applicable reuse opportunities;
evidence interventions; constructive repair certificates and their actual local
completion; API requests, estimated charges, summed request latency, wall time.
Do not turn a post-hoc score threshold into the primary endpoint. Report zero
opportunities and negative results, not only instances where the mechanism fires.

After execution, evaluator-only shadow replay checks each rejected action at its
actual pre-action checkpoint. These observations are never given to the agent.
Any false rejection or model mismatch is reported. No mid-run algorithm changes.

Zero-API tests separately compare reference and probe costs profile-by-profile,
demonstrate constructive repair, changed-context abstention and cache-vs-rule
generalization. These are mechanism checks, not independent game performance.
Persist source hashes, initial hashes, traces, API audit and aggregate tables.
Credentials and serialized private checkpoints must never be committed.
