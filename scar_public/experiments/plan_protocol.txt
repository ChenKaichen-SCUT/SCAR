Local requirement-plan revision: development protocol, 2026-10-18

Replace the repair selector with a high-level method proposer and public action
compiler. Keep the underlying actor, tasks, and public observation parser.
LLM methods: source, observed recipe, access, or accessible container. Refer to
stable evidence/site IDs rather than generating quotations/route commands.
Unknown causal relations remain hypotheses. Known public ingredients may be
compiled automatically; missing ingredients retain the parent recipe. No reverse
edge, hidden transition, unseen recipe or game-specific entity rule is supplied.
Offered exits with unobserved destinations are trials, not guaranteed paths.

Compile only the next action. Re-read actual state after every action, preserve
the root requirement, and revise the unresolved child. Separate arrival/source/
acquisition, capacity, visibility, recipe execution and true task fulfillment.
Craft output is not assumed held. Partial acquisition can help a quantity need.
Container inspection selects retrieval only when actual contents support it.
Capacity repair uses an accessible inspected container for an unrelated item;
otherwise keep the source and expose the unresolved capacity condition.
Use at most 4 dependency levels, 64 route-search nodes, 16 actions/plan and the
same total 12 method calls (10 ordinary, 2 reserved for trial feedback). Urgent
actor actions yield first. Inapplicable methods cannot force arbitrary action.
No information-value theorem, complete task semantics or safety claim.

Freeze before paid calls. First freeze: 160 targeted/regression tests pass.
Evaluate once on the same four development worlds, max 300 environment actions:
mark_r0, mark_r1, metropolis_r1, metropolis_7537. Reuse exact original baseline,
h1/h2 and objective o1/o2 calls. Do not pay to rerun frozen baselines. Retain all
scores, losses, trajectories, costs and source digests. Trace every actual action
with an exact private-environment replay; private state never enters the policy.

(the failed library material-source trial) and objective-o2 Mark-r0 through
action 59 (successful arrival at the actual material source). Compare unchanged
objective-o3 policy with this plan arm from identical snapshots/public history.
The pending trial's requirement binding is evaluator-supplied, not evidence of
automatic parsing. Legacy h2 already spent 12 calls: both arms receive exactly
two supplemental method/revision calls via a local counter set to 10, explicitly
separate from native whole-game results. For the positive control retain the

requirement fulfillment. All normal actor calls are also recorded. The criterion
is actual acquisition/score change and cost, not changed wording or admission.
No new source, route, object, recipe or successful remedy is supplied by evaluator.

All these worlds and selected states are development data. This is not a fresh
independent benchmark, a repeatability estimate or a significance claim. If no
valid recovery method is found, report failure to find one; do not claim that
the state is unsolvable. Positive unit cases are not game-performance evidence.
