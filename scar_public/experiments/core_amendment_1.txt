Implementation correction before restarting the independent evaluation
2026-10-17

The first batch is INVALID for the intended pure execution-authority contrast.
No aggregate task outcomes were analyzed to select this correction.

Trigger: the zero-API paired-prefix audit found packet divergence in mark_r2.
Diagnosis: at step60 both arms chose craft1 copper_sword. The checked gate
rewrote the method frame and resource_target even though the actual command was
unchanged. Consequently prompts differed from step61, and packets differed at
step66, before the first physical action difference. This violates the intended
"only action authority differs" control. It is an implementation defect, not
evidence that checked execution improves or harms reward.

Correction: agreement preserves ALL actor fields. The gate changes frame/target
only when it actually substitutes a different command. New regression checks
cover full-field equality on agreement. The paired runner asserts identical
public inputs, packets, initial/final LLM proposals and notebook state after
every equal-action prefix step. Transition coupling uses identical full action
prefixes rather than an incomplete state abstraction. Checks stop on violation.

All first-batch logs, source and fees remain archived at scar_core_20261017.
Stopped/in-flight API attempts remain in the charge-uncertainty accounting.
The corrected batch uses a new frozen source and nine NEW environment draws in
scar_core_valid_20261017. Same four arms,300 steps,3 repeats per game, models,
statistical comparisons and decision threshold. No selecting successful draws,
no replacing bad outcomes, and no reuse of first-batch worlds as held-out data.

This correction does not add a new planning heuristic or use reward feedback.
The first batch and smoke runs are excluded from the formal effect estimate,
but included in total development expense and disclosure.
