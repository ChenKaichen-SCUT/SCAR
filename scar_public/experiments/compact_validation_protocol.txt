SCAR compact continuation: small independent-instance screen, 2026-10-17

Scope fixed before generating new worlds or requesting evaluation responses.
One fresh reset(seed=None) in each available upstream game: remnant, mark,
metropolis. All three were development families. These are independent new
instances, NOT three unseen task families: the installed upstream supplies only
these games. No replacement of unfavorable draws, no selection by outcomes.
This 3-block screen cannot establish significance or generalization stability.

Freeze the current GenericContinuationAgent, without tuning the mechanism on
the two audited regressions. The repair_trigger hook is an identity refactor;
the only behavioral addition is an experimental scheduled control. Freeze a
hash manifest of actor, runner, this protocol and all analysis scripts first.
No entity names, game IDs, rewards or hidden state enter the decision rule.

Four arms per initial snapshot; at most300 environment actions each:
  continuation_generic: compact evidence-triggered reconsideration with checks.
  checked: same core without continuation repair, a mechanism-off control.
  sentry: existing author-code Sentry adaptation, unchanged decoding/settings.
  continuation_scheduled: same compact query and final checks, but triggered on
    a predetermined evenly spaced time grid, not repetition/failure evidence.

Timing-control budget is defined prospectively as follows. After compact ends,
let K be its number of continuation query invocations (not formatting retries).
The scheduler receives only K, never its score, history, triggers or action times.
Set zero-based due times floor((i+1)*300/(K+1)), i=0..K-1. Keep combat/urgent-action
protection and the public task/menu eligibility checks. Unused due calls carry
forward to the next eligible turn; at most one call per turn. No spending after
terminal or beyond300. Report requested K, actual calls and any shortfall.
This is a retrospective count-matched compute control, not an online baseline;
an oracle scalar K is available to it. It does not equalize tokens, formatting
retries, core calls, or realized calls if the policy terminates early. A residual
quota mismatch makes a timing-only inference inconclusive. K=0 uses no queries.

Run the first3 arms in one paired process per family. Then run the scheduled arm
on the same frozen initial snapshot, hash seed, environment version, and exact
API response cache. Same-step identical requests share responses. Different
blocks have separate caches. All logical calls are logged, including cache hits.
Any exact-prefix state/action pair must have equal public feedback/state digest.
Restore environment/Python/NumPy RNG AFTER actor computation and before stepping.
Randomly draw and record process hash seeds before creating worlds. Match the
same hash seed in all replay and scheduled subprocesses.

Maximum12 episodes /3600 actions; no extra repetitions based on observed signs.
DeepSeek-flash, temperature.7/top_p.8/1536 actor output tokens, existing baseline
Sentry settings: W5/H10/top_k5/label_cap2, same model auxiliary temp0/4096tokens.
This differs from the official TTCL model/budget and is not its leaderboard.
External baselines must be run for these new worlds; subsequent reuse is frozen.

Primary outcome: per-instance raw main-quest score at terminal or300 actions.
Report every arm and paired delta, completion, deaths, actions, semantic failures,
repair requests/changes, additional tokens, logical calls, actual paid requests,
latency and historical-formula cost estimate including failed attempts/retries.
Raw score scales differ by game: mean/sum is only descriptive, not calibrated.
With one draw per family, do not claim statistical significance or stability.
Screen for expansion only if compact beats checked and sentry on at least2/3
families, loses on none, and the same directional advantage holds against the
scheduled control with no quota shortfall. Otherwise report which criterion
failed and stop expansion; no tuning using these outcomes within this study.
Keep completion/death regressions visible even if score improves.

Audit all completed transitions offline with no API. Evaluate changed compact
actions against the original proposal for ONE step from the exact same state;
report immediate failures and scores without claiming full-policy causal value.
Verify all source hashes after execution; record source and environment receipts.
Store private snapshots only on the experiment server; publish public traces,
API payloads/responses after secret scanning, costs and source hashes separately.
Any harness defect invalidates affected data with a written amendment. Never
repair a policy mid-evaluation. Do not edit the manuscript in this study.
