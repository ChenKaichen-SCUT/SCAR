Persistent unresolved Sentry cases, frozen development pilot 2026-10-18

Same author Sentry and clean AgentOdyssey ReAct/LongContext actor as the previous
foundation pilot. No ordinary historical-retrieval augmentation. Trigger only
after author Sentry reports a completed soft recovery unresolved. Retain the
task condition, blocking explanation, literal observation references, attempted
operation and actual result. A model proposes one next operation to change a
condition or test two explanations with different downstream decisions.
Next card incorporates ACTUAL executed action, including when advice was ignored.
Same case goal is held fixed; a current observation reference is required for
closure. Evidence provenance is checked, semantic entailment is NOT guaranteed.
Unknown but grounded operations remain eligible. This is a heuristic algorithm.

Two variants: advice inserts the same structured card into ordinary actor
history; execute also selects its schema-checked next operation, only in the
immediately expected observation. Both run the ordinary actor, same model and
decoding, and retain actual actions in its conversation. Original Sentry still
detects, verifies and learns normally. New operation scheduling is limited to
six actions per failed verification and30 extra model calls per game, including
up to two structural-output attempts per decision. Unresolved cases remain
stored on quota suspension; no success is inferred. All public outcomes are
available to the repair model, with no top-K retrieval. No entity-specific rule.

Reuse all three foundation worlds, original Sentry and plain actor results;
these are development worlds, not independent validation. No paid baseline rerun.
To couple original prefixes, random playbook entry identifiers are copied ONLY
after exact equality of their public content. After trajectory divergence,
identifiers are derived from content and cycle to couple identical new calls.
IDs do not encode task state. Other author Sentry behavior is unchanged.

Freeze before paid calls. First execute advice/execute through12 actions after
the first failed verification in EACH world. Inspect literal outcomes, card
validation and equal-state first choices. Then continue those SAME cached runs
to300 actual actions, not new restarts/samples. Do not select only good worlds.
No policy modification after inspecting scores in this batch. Include all
failures, pauses, exhausted quotas, rejected cards, tokens and charges.
Every executed action gets exact snapshot replay; assert original prefix state
equality. Actual task scores are evaluation-only and never controller input.
If structural errors block execution, preserve the failed version and logs;
any repair must be an explicitly recorded new freeze.

Primary question: does persistent outcome-conditioned repair improve main-task
score relative to original Sentry, and does explicit execution improve on advice?
Do not count a valid citation, a changed action, or Sentry's own recovery label
as proof of task benefit. One draw in three familiar worlds cannot establish
stable improvement or cross-domain generalization. Formal evaluation requires
positive development evidence, a frozen algorithm and independent repetitions.
