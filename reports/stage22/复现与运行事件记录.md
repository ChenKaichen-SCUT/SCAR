# 复现与运行事件记录

正式冻结提交：`7621a9417294ce3cc1ce54d1b09bb049eae9e631`。本文件只记录基础设施和分析复现事件，不为任何方法删局、补跑或改策略。

## CPU 检索资源调整

Voyager 使用官方 Qwen3-Embedding-0.6B；开始时 OMP/MKL 各 1 线程。模型请求通常约 1 秒，主要等待在 CPU 检索。用完全无游戏内容的固定文本测量：1 线程 48.634 秒，4 线程 14.766 秒，向量最大逐元素差异 0、余弦相似度 1。该测量未调用生成模型，原始记录在 `cpu_embedding_benchmark.json`，复算代码在 `cpu_benchmark.py`。

只将三个 Voyager 工作进程调整为 4 CPU 线程；SCAR 及官方策略代码、模型参数、权重和 embedding 精度不变。操作先暂停进程，确认没有待定 API 请求，保存原始请求前缀哈希及步骤哈希，再从原检查点续接。检查点分别为 remnant 第 38 步、mark 第 35 步、metropolis 第 33 步。未完成动作如已有付费回复，由严格签名缓存复用。没有重新初始化世界、重抽模型答案或另选较好结果。

原调度器会把人为结束的旧工作进程记为 `worker_crash`，这是运行事件，不是 Voyager 的游戏失败；其后独立续跑进程沿用同一个目录和初始时刻。`resource_resume.json` 保留操作及最终前缀/步骤不变核验；各局最终状态以原唯一轨迹的 `summary.json` 为准。总用时包含加载、暂停和恢复开销，不能把它当成严格硬件计时基准。

## 同种子不等于逐字节相同初态

离线回放最初未通过初态哈希检查。逐项比较各局保存的官方 pre-bootstrap config 后发现，全部差异位于 `world.auxiliary.ing_to_obj_map`：官方 `games/base/world.py` 在 `_synthesize_objects` 中执行 `list(set(...))`，列表成员相同，但未固定 `PYTHONHASHSEED` 的独立进程可产生不同排列。五方法的物理初始内容在这些列表顺序之外相同，初始公开文本完全一致。

进一步核对发现，影响不止展示顺序：metropolis 官方主线初始化中，集合遍历和相同距离的并列排序也会改变后续主线的场景位置参数。五局的 `ch2_bench_area`、`ch2_judge_area`、部分第三章地点存在差异；pre-bootstrap 状态相同并不代表 reset 后的完整场景一致。remnant 与 mark 的已保存主线地点参数在五方法之间一致。完整参数差异将随最终核验保存。

这些不是可以隐去的无关差异：配方列表影响模型上下文，主线地点还可能影响任务难度。本轮仍按已冻结的官方原生环境完成第一轮，不事后统一顺序、改环境或重跑。结果是相同环境版本和 seed 的单次研究比较，**不具备严格的同状态配对条件，尤其不能把 metropolis 分差完全归因于算法**。三游戏 pre-bootstrap 原始差异清单见 `initial_state_comparison.json`，每局真实原生初态保存为 `native_prebootstrap_config.json.gz`。

离线回放从各局保存的原始配方展示顺序及原生主线场景参数恢复，随后核对实际动作、反馈、奖励及状态。场景参数恢复仅覆盖原生 bootstrap 本来就产生的键，保留其 RNG 消耗，不注入后续完成状态。这种恢复只发生在分析进程，不改变正式轨迹，也不把隐藏配方或场景配置送进 agent。若未来做新的正式评测，应预先冻结进程哈希种子并测试此问题，但本轮不启动新的评测样本。

## 界限

资源调整不使用测试游戏内容或奖励作为依据；决定依据是无游戏文本的 CPU 基准。回放脚本开发中出现的断言失败属于零 API 分析调试，不是重新执行失败实验或筛选成功样本。冻结清单及历史文件完整性由最终 `verification.json` 独立核对。

## 离线回放的严格边界

完整原始轨迹、逐步累计评分、最终 config 和官方评分脚本之间的核对覆盖全部 15 局。原生离线重放另外逐步比较公开反馈、reward、done 和完整 state hash；首次不匹配即停止，不以“分数暂时一样”冒充全状态相同。回放收据保留已验证前缀与第一处分歧，不能把总体验证通过解释为所有原生回放通过。

例如 remnant / Stage18-Fixed 在 a87 首次开启支线任务时，公开反馈和奖励仍匹配，但内部分支任务生成状态不同。metropolis 的 DAG announced 列表也有集合序列化顺序影响。后者未被自动忽略或改写为通过。只在已严格匹配的状态前缀上保留局部动作反事实，后续损失不做已验证声明。

恢复 Voyager 的新进程未固定哈希种子；虽然检查点、RNG、记忆、已付费请求及模型 embedding 输出保持一致，仍不能证明后续涉及集合遍历的游戏生成与“不恢复的未来”相同。这是一次唯一运行的恢复事件和复现限制，不是新样本或择优。后续正式评测需要先解决并预注册此类基础设施问题。
