# 官方评测协议核验

核验日期：2026-10-13 UTC。本轮为 **300 步、DeepSeek Flash 的非排名研究预实验**，不能申报为 TTCL 最终 500 步排名。

重新克隆官方仓库并在线核验 HEAD 为 `248430692a9d4a61d38c6c03ab2126287faaf450`，与之前依赖提交一致。新独立检出位于 `/mnt/Space0/scar_dependencies/agentodyssey_stage22`。冻结清单记录所有官方文件哈希，原依赖不改。

## 官方定义与采用方式

- [官方 README 的 TTCL 协议](https://github.com/agentodyssey/agentodyssey#ttcl-challenge-evaluation)：游戏 remnant / mark / metropolis，三游戏原始主线奖励无权平均；原始辅助奖励总和的三游戏无权平均作为并列判定；每游戏清空记忆。正式要求 500 步与 Qwen3-4B 或 Qwen3.5-4B。本轮按指引使用 300 步。
- [官方 challenge_eval.py](https://github.com/agentodyssey/agentodyssey/blob/248430692a9d4a61d38c6c03ab2126287faaf450/challenge_eval.py)：从原生 config 读取 `scores[agent_id].quest`；辅助为 `side_quest + exploration + craft + unique_kill`。尤其 defeat 实际取 `unique_kill`，不能取累计 kill 或 XP 总分。
- [评估接口文档](https://agentodyssey.github.io/docs/game-apis/full-api-reference) 与 [Agent 实现文档](https://agentodyssey.github.io/docs/agent/implementing-agents)：返回动作、输入 token、输出 token、原始回复；本轮使用官方 agent 类、原生环境的 reset/step/update_scores/update_config。自有 harness 只增加观测回调、原始请求审计和准确 checkpoint。
- [通用指标页面](https://agentodyssey.github.io/docs/evaluation-metrics) 还介绍归一化组合图，但它不是当前 TTCL 排名公式。本轮不使用这种归一化，也不按游戏难度加权。

主线每个原生 `quest_stage_advanced` 事件加 1。辅助项统计完成支线、探索区域、首次制作物品类型、首次击败 NPC 类型。教程期间原生奖励抑制不改；教程也占 300 步。只有官方 `done` 或动作上限结束游戏，不按自定义制作成功、死亡次数、wait 循环提前终止。异常独立标记为基础设施终止，不能伪称正常完成。

## 公平性配置

三游戏各五方法各一次，共 15 局。环境 seed=42；远端模型采样没有严格可重放种子承诺，不能用单样本推断显著性。全部从各游戏官方 initial.json 重置，无预执行动作，无历史轨迹，关闭 valid_actions 隐藏可行动作提示。新进程和新目录隔离各游戏状态；Voyager 技能库也清空。

模型统一为 `deepseek-flash`，temperature=0.7，top_p=0.8，presence_penalty=1.5，thinking=disabled，max_tokens=768，JSON response_format。这与原 Stage18 小任务的传输层默认采样参数并非完全相同，但五种当前方法相同。所有角色调用均用同一模型和输出上限。LongContext 原样增长，不设置特殊截断或单独提额；超限请求须记录，不能暗中改成摘要。STM 窗口 5；额外 reflection/summarization 关闭；Voyager 固有课程、critic、skill distillation 保留。

本地 16 逻辑 CPU、约 29 GiB RAM，无可用 CUDA GPU，无已缓存合规 Qwen 4B 生成模型。CPU 并非理论上不能运行 Qwen；考虑 15 局长上下文及吞吐资源约束，采用指引允许的 Flash 分支。实验不能用于判断合规 Qwen 下的正式排名。Voyager 沿用官方 Qwen3-Embedding-0.6B，固定 revision `97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3`，CPU 执行。

## 计费与异常

[核验时的 DeepSeek 官方价格](https://api-docs.deepseek.com/quick_start/pricing/)：Flash 缓存命中/未命中/输出每百万 token 峰时分别 $0.006/$0.3/$1.2，非峰半价；请求按 API 返回时间记录适用价格。报告给出 usage 计价、峰时参考值和未决保留值；usage 计价不是账户发票，也不推断赠金扣减。角色额外调用独立入账。只有明确未收费的 HTTP 429 可有限重试，已付费的坏 JSON 不重采样，未知计费立即保留证据并停止该局。

内部防失控额度总 $100、每局 $25，并非计划消费额，未恢复过去的 $20 限制。按全部 4500 动作、长上下文平均约 12 万输入 token 的保守情景估计费用主要来自 LongContext，实际依缓存和轨迹变化；不为提高成绩追加样本。

最终对每种方法分别直接运行未改动的 `challenge_eval.py`，保存文本和 JSON 输出。该脚本只对超过 500 步发警告，不会自动判定 300 步或错误模型不合规，因此本报告和汇总表必须始终明确标注研究预实验。

## 执行后的协议偏差核验

同种子与初始公开文本相同已经核验，但不能据此宣称完整场景严格配对。官方集合遍历受未固定的 `PYTHONHASHSEED` 影响：三游戏配方展示顺序不一，metropolis 的主线地点参数也有差异。动态支线生成和 DAG 集合序列化使部分离线回放无法逐步复现。详见 [复现与运行事件记录](复现与运行事件记录.md)、`initial_state_comparison.json` 与 `generated_scenario_comparison.json`。本轮没有事后改环境或重抽样消除差异；原始官方得分全部报告，算法因果结论受此限制。

Voyager 的 CPU 线程调整通过原检查点续接，已提交前缀和付费请求不变。但恢复新进程同样没有固定哈希种子，因此不能声称它与“不中断进程的未来轨迹”逐字节等价。CPU embedding 的同值测试只证明该算子输出同值，不证明整个原生游戏未来生成不受重启影响。
