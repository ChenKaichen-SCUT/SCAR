# Stage18-Fixed 工程修复与算法差异审计

本轮研究算法来自原始冻结提交 `2c2f7ecc03b0e326f26cdf85ce13e2415b374e33`。冻结时记录的 337 个 Python 文件逐一校验，全部与当前文件一致。新增 `scar_stage18_fixed` 独立入口引用这些原文件；不修改历史文件，不导入 Stage19、Stage20 或 Stage21。机器可验证凭据见 `results/stage22/freeze.json`、`preflight.json`。

## 原始算法边界

原 Stage18 是 STM5 LLM 提案加 S1/P1/P3 控制器：保存公开资源、配方证据、FIFO 工作队列、尝试及失败记录；以公开单次名义需求限制收取量；对已观察的携带损伤保存有条件后果证据；通过公开前置条件评估仲裁 LLM 和控制器候选。候选在副本上计算，只有实际执行的探查才提交额度。模型事实视图至多 48 条、6000 字符。未新增子目标规划、探索额度、规则推断、记忆检索或技能学习。

它原来接收实验者指定的制作目标。当前协议是官方主线，因此不能把一套新主线规划算法藏在接口内。适配只启用历史上已有的 `Controller.follow_public`，使用原 `PublicState` 的 `Required action / Your task is / Objective` 文本解析；缺少可解析目标时不推断新目标。原代码可能保留旧目标或把动作对象当成物品需求，这属于需要如实测量的既有能力边界。自然语言主线信息仍原样进入所有方法的公开观测。

## 修复与适配清单

| 编号 | 原始故障 / 协议不匹配 | 最小复现 | 最小变更 | 回归证据 |
|---|---|---|---|---|
| F1 | 官方 STM 调用 `cfg.construct_user_prompt_long_context`，默认配置无此方法 | 默认 FixedSizeMemoryAgentConfig 调用该方法抛 AttributeError | 适配配置委托官方 LongContextAgent 已有同名实现，未重写记忆逻辑 | `test_original_stm_missing_method_reproduced`、五算法接口检查 |
| F2 | Voyager 在无 available_actions 时重新构造普通 VoyagerAgentConfig，不能保留外部提供者接入 | 检查官方构造分支及注入 provider 的身份 | 从一开始提供完整 VoyagerAgentConfig 与动作模式，保留官方课程、判定、提炼、检索代码 | `test_all_five_interfaces_and_memory_reset` 检查 provider 身份、2/4 次角色调用及 checkpoint |
| A1 | Stage18 内部 P3 时钟固定 100，外部评测为 300 | 同一个合成就绪状态设 step16=99：原 finish 拒绝两步收尾 | 只替换函数独立 globals 中的 EPISODE_ACTIONS=300；FINISH_WINDOW=6 不变 | `test_late_horizon_minimal_reproduction`，恢复后仍为 300 |
| A2 | 官方逐步接口不自动调用自定义控制器的反馈入口 | 只调用 act/step 不会更新 controller/facts | 每个真实 step 后恰好一次 observe_transition；首次只输入当前公开观测，后续事实视图同步已有目标通道 | 五算法接口检查、公开目标合成反馈及状态保存恢复 |
| A3 | Stage18 实验脚本注入制作目标及历史前缀，不是官方主线初态 | 原 `make_method` 强制 `craft 1 target` | 新入口不调用该实验工厂；从官方 reset 开始，无前缀、无旧轨迹，原公开目标通道取值 | 初态公开文件、运行配置、逐局初态哈希留存；跨方法完整状态不相同，见运行审计 |
| A4 | Voyager 返回的 token 仅包含动作调用，漏记课程/判定/提炼 | 合成首步两次请求但 `_act` 只返回动作 token | 在共享模型传输层记录每次原始请求及 usage，不改 Voyager 决策 | 角色级 requests 与独立账本统计 |

A1–A4 是协议/计量适配，不宣称它们是原制作实验中的算法错误。F2 是注入外部共享提供者时的兼容性缺口，不能推断官方默认模型配置下 Voyager 必然不可用。

## 代码等价性与输入差异

`Controller18Fixed.choose`、`legacy_copy`、`Stage18Fixed._act`、构造和加载方法直接复用原函数的 **同一 code object**。只在函数 globals 中绑定预算适配类，保证试算、语法回滚、保存恢复均不偷偷回到 100 步。40 个合成状态/提案配对除 `remaining_actions` 字段外，动作和控制器状态相等。原 Stage18 的 9 个工程单测原封不动运行。

这证明相同输入下原决策代码被保留，不意味着新旧实验端到端行为相同：外部任务、初态、300 步时钟、共享采样参数均按新协议改变。五方法使用官方默认 JSON 解析器；异常响应保留并按官方行为返回 wait，不进行付费格式重采样。原 Stage18 专用实验 provider 的强制重试/严格解析不移植到这一共享接口。该传输/异常处理差异列入报告，不冒充策略改进。

官方四个基线源码不改；合成测试以网络阻断验证接口、内存清空、checkpoint、原始方法等价性。测试不加载三个排名游戏，不读取历史轨迹。Voyager 的官方 0.6B embedding 模型仅用两段无游戏内容文本测试 CPU 推理，下载权重不提交 GitHub。

## 保留的限制

原 `set_goal` 会重置 P3 的局部 step16 时钟；本轮保留该行为，外部 300 步上限独立强制执行。不能把内部局部剩余额度当成全局剩余预算。原公开目标解析覆盖有限、收取量和批量策略、FIFO、风险判定、探索上限、事实截取顺序均冻结。正式运行后即使观察到负面结果，也不调整这些行为或重跑失败局。
