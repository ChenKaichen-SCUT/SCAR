使用Python3.12和官方AgentOdyssey提交`248430692a9d4a61d38c6c03ab2126287faaf450`，项目安装方法沿用仓库原说明。下载的引擎、模型、缓存和私密凭据不在本次提交中。Stage9源代码、生成的Robot初态、轨迹、模型请求与中文分析单独保存，不改旧Stage8文件。

## 已保存实验的零API复现

进入SCAR仓库并使用已安装项目依赖、官方引擎模块的Python环境：

```bash
export PYTHONHASHSEED=0 OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1
export AGENTODYSSEY_ROOT=/path/to/agentodyssey
python -m pytest -q tests/test_stage9.py tests/test_stage8.py tests/test_stage7.py tests/test_unknown17.py tests/test_sequence.py
python -m scar_stage9.reproduce --runtime /tmp/scar9-replay --replay-saved
```

第二条命令校验策略与数据冻结哈希，重建16个初态，重放全部64局，逐动作比较原始物理状态哈希、目标和拒绝结果。它不调用模型，也不新建其他游戏环境。快照是本项目生成并移除LLM对象和凭据的可信本地实验状态，依赖相同Python与上游代码。

若需重新生成机制验收和分析，**先建立独立checkout/worktree**：下列命令会写该副本的results/stage9，不得覆盖作为原始实验记录保存的目录。

```bash
python -m scar_stage9.offline --runtime /tmp/scar9-offline
python -m scar_stage9.interpret
python -m scar_stage9.report
```

offline只从Robot历史状态取样；其16条关键重放使用固定`wait`基础提案，正确恢复动作由控制器自主生成。真实失败挑战中的一次公开目标尝试是显式设置动作，计入剩余预算。另存的negative_counterfactuals则是评测器固定后缀诊断，不能与自主恢复混算。

## 独立重新运行模型闭环

本次原始64组已结束，不需要重跑。若自行复现实验，使用独立checkout、新的空runtime以及自己的密钥文件：

```bash
python -m scar_stage9.reproduce --runtime /path/to/fresh-scar9 --run-closed-loop --key /private/keyfile --workers 12
python -m scar_stage9.finish --runtime /path/to/fresh-scar9 --workers 8
```

固定限制为16题×4配置、每局40动作、一个物理种子、全局$4、单局$0.20。reproduce默认不会付费，只有显式`--run-closed-loop`和密钥参数才启动模型；有已存在runs的目录拒绝重跑。模型非零温度、供应商响应及缓存会使独立运行结果不同，不应覆盖或替代原始结果。

finish会重新计算原始结果、局部反事实和重放核验，不修改策略或调用模型。`实验报告.md`与`research_judgment.json`记录的是本次原始实验的具体解释；新模型运行如有不同结果，需要重新解释，不能直接套用原结论。独立机器没有此前五个服务器账本时，verify只核对本次真实账本，历史累计数采用发布的比较口径并明确标记来源。

| policy code：scar_stage9/controller.py | 共享三值条件、FIFO修复、8动作/4层GPAR |

| resource_audit、batch_audit | 原生动作消耗、环境步损耗和各批量真实效果 |

| publication_checks、artifact_manifest | 发布前统计、凭据模式、文件哈希核验 |
