# ETBR算法设计及实现

基于Stage20A提交 `2b272295ff2453ff970fd80e709b28479b379687`；本轮仅运行SCAR21一次24题。Stage18—20成绩读取历史冻结结果。24题已反复用于开发，不是独立泛化集。

ETBR使用一般PublicEvidenceDelta和执行阻碍接口。当前游戏适配器提取公开制作关系、材料历史位置、区域前提、地图连接与门锁条件。NPC对话和任务阶段仅通过公开结构化接口单测；没有可靠在线文本解析时返回UNKNOWN，不声称覆盖其他游戏。

事实内容哈希不含时间戳。初始知识、重复检查、无关物品、模型猜测不能领额度。条件为：目标尚未解决；存在未消费且公开关联当前阻碍的新事实；存在合法、尚未充分尝试的入口；风险和剩余预算允许。

冻结参数：原18次探索不变；每条新证据最多1个信用，跨阻碍也不重复使用；每阻碍最多2个，每局最多6个。每个信用最多1次有效试探加3次中转；每次实际动作均计入100步。最多24次逻辑模型请求、每次最多3次接口尝试；总$3、单局$0.25。ETBR自身确定性选入口，不额外请求模型。

执行顺序：P3→可靠FIFO→公开依赖执行→已有有限试探→满足条件的ETBR→可用普通探索。多个普通未知入口时，可按需请求LLM提出一个试探；单入口与ETBR入口不需要模型。

模型上下文最多8000字符/24条证据，输出最多512 token，不发送完整历史。阶段分别记录PROBE_COMPLETED、NEW_EVIDENCE_OBTAINED、PRECONDITION_RESOLVED（公共路径/真实持有分开）、PARENT_TASK_RESUMED、TASK_PROGRESS。相关性使用公开实体关系，不使用语义全局排名或隐藏地图。

触发相关性实现的局限：适配器将整个目标依赖及相关地点都放入public_entities，范围大于当前具体阻碍的未完成链。唯一正式触发引用第9步发现charred_timber位于barracks，而第31步阻碍是oil_flask；该依据不能证明oil_flask的取得路径发生变化。故本轮实现尚未严格满足“改变当前阻碍可解决性”的强触发要求。该问题在结果审计中披露，冻结算法未修改。

固定扩额不是ETBR；一次额外行动碰巧获得有用信息也不能验证本轮证据触发准则优于固定扩额。原生单步影子分支只用于工程验收，不进入24题成功率。
