Origin 使用保存的原回复与原轨迹后缀，不增加基线采样。原完整 300 步环境回放及十个检查点哈希均先核验；恢复的 Agent 首次上下文和动作必须与原记录一致。A 的十段后缀重叠，分数不作为独立样本。

Reset 的触发条件按 OR 合并，运行后不调参：①原有登记目标的 generation 和文本连续 12 次反馈未变；②相同目标 verb/target 连续三次尝试被公开反馈拒绝；③当前公开位置已经满足 enter 目标且当前显式指令不再重复该动作，或新的显式公开指令与旧目标不同。①测量的是**登记目标停滞**，不是读取隐藏任务进度。只从旧前缀预热持续长度/失败计数，不追溯应用位置触发。满足条件后停用该 `(generation,target)` 的仲裁权，原解析器若登记新目标则自然解除这一标记。

Oracle 在每个所选检查点立即停用旧目标仲裁权。a33/a35 是主要已知机会点，其余八个是较晚同状态诊断入口，**不回退到 a33 改写历史**。Oracle 是人工指定释放时机的参照，不是完整规划/探索上界。

唯一策略差异：原仲裁原本返回 `retain_structured_default_when_evidence_does_not_resolve`，且原 LLM 提案不是 `REJECT` 时，允许返回这个已有提案。保留所有公开条件拒绝、库存容量检查、既有风险判断、存入量限制、事务提交、语法 fallback。不会生成或推荐任何新动作，不改 goal 字段，不改 STM5，不新增模型调用角色。最终执行仍可能因原有数量限制不同于原提案，必须如实记录。

三版本每个检查点共享物理状态、公开 observation、保存记忆和环境 RNG，绝对动作上限仍为 300，只有原生 done 可以提前终止。不同检查点的剩余预算不同，分别呈现分层结果。Origin 之外最多 3538 次动作决策；复用后新增 API 请求更少。本地最多十个并行进程，每个处理一对 Reset/Oracle。

为减少浪费并耦合相同输入的随机采样：仅在同一检查点、同一原动作号、同一环境全状态哈希及逐字相同模型 messages 时跨版本复用回复；满足原状态/原输入则直接用 Stage22 已付费回复。不同检查点不共享新回复。两个政策若整个续跑相同，仍各有逻辑轨迹，但共享样本和费用须单列。所有复用都有来源索引；不得把复用次数当作新增请求，也不得把共同样本当独立重复。

主结果包含第一章完成、主线增量和各公开关键阶段。预登记“明显恢复”描述性门槛：某版本至少 **5/10 检查点获得 ≥1 主线增量，或至少一个检查点完成第一章**。这不是显著性检验；同时完整报告每个检查点、≥1/≥3 奖励覆盖及剩余预算，不能隐藏未达阈值的正向或负向情况。

分类：Reset 达门槛 → `ENGINEERING_FIX_SUPPORTED`；仅 Oracle 达门槛 → `CONTROLLER_LIMIT_CONFIRMED`；两者均未达 → `DESIGN_LIMIT_CONFIRMED`，解释范围限于此仲裁消融及给定预算。Oracle 失败不能单独证明“基础 LLM 没有规划能力”，因为按用户指定的口径仍保留陈旧模型输入与其他控制检查。若有基础设施中断或未完成局，先解决/注明，不能提前当失败套分类。

有效性同时报告“环境接受的非 wait 动作比例”和“伴随可观察进展的动作比例”，避免把任意走动算任务进展。新状态计数排除时间、HP、stamina；区域、物品与 NPC 的自然变化也可能来自环境，不能把全部状态新颖性归因于探索。stale goal 文本持续长度与 stale goal **仍有仲裁权**的持续长度分开统计。
