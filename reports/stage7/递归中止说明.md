# 冻结策略中的递归中止

正式 C5 的 `sequence-8d8d1a4fc7768d57`（spire_pike）在完成 26 个环境动作后中止。下一次模型请求已返回基础提案 `pick up orrery_blade`，控制器尚未返回最终动作，因此这次请求有费用、没有第 27 个环境动作。

当时公开 FIFO 队列为 `astrolabe_core, spire_pike, orrery_blade`，剩余探索额度尚未用完；但当前及记忆位置均没有所需工作台。`_station()` 为未知位置工作台调用 `_explore()`，知识缺口探索又选到需要该工作台的前向制作候选，随后再次调用 `_station()`。没有动作被返回，探索步数预算也无法递增，最终触发 `RecursionError`。

独立审计保持相同检查点、公开观察及已付费基础提案，两次重现异常。分别关闭 A、C 或 D 仍重现；关闭 B 可返回 `craft 1 brass_blank`。后者只证明局部递归依赖该探索路径，不证明关闭 B 会完成整局目标。原始错误栈、输入状态及单步引擎分支保存在 `results/stage7/method_terminations.json` 和 `method_errors/`。

冻结运行器将一般异常记为 `failed`。本轮没有重写这个原始状态；根据可重现的策略异常，将其事后判为 **方法中止**，计入 C5 的完整 17 例分母。全部请求费用保留，代码未因正式结果调整，也没有补跑该任务。

后续实现应给“工作台查询—探索候选”调用链加入正在求解的对象/站点集合，遇到环时转向独立的公开位置探索或返回不可执行，而不是再次请求同一前向候选。这应在下一轮策略版本中先做零 API 回归，再独立冻结。本轮不将未经正式验证的修复混入已报告的 C5，也不追加随机种子、动作上限或 API 实验。
