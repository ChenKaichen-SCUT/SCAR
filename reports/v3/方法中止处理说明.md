# V3 方法中止处理说明

本批 445 个困难诊断任务均已实际调用模型：443 个正常结束，2 个 SCARV3Agent 在有界格式修复后无法产生符合公开动作签名的候选，提前中止。原始 `summary.json` 和 `status.json` 仍保留 `failed`、错误文本、实际动作数和全部费用，没有改写为正常完成。

两例为：

| 案例 | 已执行动作 | API 调用 | 本局费用 | 原始错误 |
|---|---:|---:|---:|---|
| hard-3305cc8bc3d10506 | 2 | 4 | $0.001031748 | No public-signature-valid action after bounded V3 format repair |
| hard-e6ecbaec762af88a | 10 | 13 | $0.008177964 | 同上 |

两例的基础提案和修复请求均成功返回，最后两条请求状态为 `ok`。模型输出了带多余数量参数的 `pick up 2 steel_ingot`、`take out 1 glass_shard small_bag_0` 等动作；限定候选中没有通过签名检查的动作，触发了冻结 V3 已实现的中止逻辑。因此，这是被实际观察到的方法失败。

初版调度器将任何 `failed` 状态视为阶段未完成，导致困难诊断结束后没有启动长程。检查原始证据后，现补充**事后明确的结果处理口径**：

1. 精确匹配公开签名检查中止错误，且基础提案和修复 API 请求成功的任务，作为已评测的方法中止结果。
2. 保留失败结果进入该方法的全部 89 个 family 分母。两例目标未达成，Recovery@10/@20/@40 均为失败，不捏造余下动作，也不把实际 2/10 步改成跑满 40 步。
3. 不给这些任务额外模型尝试。原始状态、调用、费用和错误均保持不变；报告分别列出正常完成、方法中止和未完成。
4. HTTP/连接/限速故障、未知异常或缺乏请求证据仍为未完成，不能按上述方式补齐结果。
5. 规则以错误性质判断，适用于所有方法，不按方法成绩选择排除。

这是在看到两次中止之后补充的统计与调度口径，不能声称预先注册。后续报告必须披露这一点。没有修改 `scar_v3/` 中任何冻结运行或策略文件、五种方法、测试案例、种子、动作预算或模型设置。执行哈希和任务 ID 继续沿用原批次；新的外部分析入口 `scripts/analyze_v3_results.py` 保留这种结果分类，原分析代码也保留。

因此，困难诊断状态应写为 **445/445 已评测：443 正常结束、2 方法中止**，而不是“445 个正常完成”或“只计算 443 个结果”。随后长程按原计划执行，共 15 局、种子 909、每局最多 200 步。

长程执行结束后，另有 `long-SCARV3Agent-remnant-909-d926f725b95f` 出现相同方法中止：实际执行 133 步，观察到主线奖励 1，费用 $0.067024812。最后两次基础提案与修复请求均正常返回，按已明确的同一规则保留为失败；不补算未执行的 67 步，也不额外重试。其余 14 局均跑满 200 步，因此长程应写为 **15/15 已评测：14 正常结束、1 方法中止**。

新增测试验证“真实格式中止计入失败且不改写原记录”和“传输故障不能误判为已评测”；服务器全部 68 项测试通过。最终审计包括这三例已提交的实际步骤，1,388 次抽查全部精确重放，原始轨迹导出包含失败记录。科研结论与费用见 [最终实验报告](最终实验报告.md)。
