先按仓库 README 安装固定提交的官方 AgentOdyssey 及 CPU 环境。`scar_v3/` 是新增实现；不要修改或重新生成 V1/V2 的冻结材料。

服务器现有路径：

- 项目 `/root/scar_workspace/project`
- Python `/root/scar_workspace/venv/bin/python`
- 官方引擎 `/root/scar_workspace/dependencies/agentodyssey`

- 本轮运行 `/root/scar_workspace/runtime_v3`

```bash
cd /root/scar_workspace/project

SCAR_PY=/root/scar_workspace/venv/bin/python

```

## 无 API 费用的复核

```bash
"$SCAR_PY" -m pytest -q
"$SCAR_PY" -m scripts.validate_v3_dataset \
  --cases "$SCAR_CASES" --manifest "$SCAR_RUNTIME/ao_fr_hard/manifest.json" \
  --output "$SCAR_RUNTIME/revalidation.json" --workers 8
"$SCAR_PY" -m scripts.audit_v3_learning --cases "$SCAR_CASES" \
  --output "$SCAR_RUNTIME/component_recheck" --include-test
"$SCAR_PY" -m scripts.check_v3_runner --cases "$SCAR_CASES" \
  --runtime "$SCAR_RUNTIME/runner_recheck" --output "$SCAR_RUNTIME/runner_recheck.json"
"$SCAR_PY" -m scar_v3.run --runtime "$SCAR_RUNTIME" \
  --cumulative-ledger /root/scar_workspace/runtime/budget.sqlite \
  --cases "$SCAR_CASES" --stage hard --workers 8
```

最后一条默认只保存计划，不调用模型。`check_v3_runner` 使用确定性测试 Provider，真实执行引擎，但不产生模型性能结果。组件验证的开发训练模型只用于该独立审计，正式 Agent 工厂不会加载它。

## 数据构造复现

冻结数据不可覆盖。只在新的输出目录重新构造：

```bash
"$SCAR_PY" -m scar_v3.hard --output /new/path/hard_build --limit 200 --nodes 1500 --workers 8
"$SCAR_PY" -m scar_v3.mine --historical-runtime /root/scar_workspace/runtime \
  --output /new/path/hard_natural --workers 8
"$SCAR_PY" -m scar_v3.freeze_data --synthetic /new/path/hard_build \
  --natural /new/path/hard_natural --historical-runtime /root/scar_workspace/runtime \
  --output /new/path/frozen --limit 120 --workers 8
```

136 个可构造配方在 `--limit 200` 内全部尝试。自然案例依赖服务器上的原始 STM 轨迹和可信快照；只有 GitHub 元数据时不能独立恢复那些母状态。发布的 `results/v3/dataset/cases.json` 保存公开历史、目标、见证与来源，`synthetic_initial_edits.json` 保存初始编辑。完整物理快照及原始引擎日志仍在服务器，不上传第三方引擎/模型或 pickle。异机重建后的绝对路径不同会改变整个 cases 文档哈希，应另建 manifest，不伪装为原冻结哈希；逐例物理状态和见证可另外对照。

## 正式执行（已获得解除原上限的授权）

用户已授权本批必需实验暂时忽略原 $20 上限，当前配置为 `total_budget_usd: null` 并记录明确授权标记；依然使用同一累计账本。不要清零费用或扩大实验范围。详见《执行授权与范围》。服务器当前已有后台调度，不要另外重复启动下面的顺序运行命令；这些命令用于停机后的受控续跑。

```bash
for SCAR_STAGE in dev hard long; do
  "$SCAR_PY" -m scar_v3.run --runtime "$SCAR_RUNTIME" \
    --cumulative-ledger /root/scar_workspace/runtime/budget.sqlite \
    --cases "$SCAR_CASES" --stage "$SCAR_STAGE" --workers 8 \
    --key-file /secure/path/to/key --execute || break
done
"$SCAR_PY" -m scar_v3.analyze --runtime "$SCAR_RUNTIME" --cases "$SCAR_CASES" \
  --output results/v3/formal
```

`dev` 为开发集按固定顺序每游戏一个 V3 预检，最多 20 步，共 3 局。正式 `hard` 为 89 测试 family × 五方法 × 最多 40 步，达成公开物理目标提前停止；`long` 为三个游戏 × 五方法 × 种子 909 × 最多 200 步。所有正式基线实际重跑；不复用旧成绩。自动并行仅跨案例，单局动作顺序执行。若更改策略，必须另记版本、重新验证并明确已接触旧冻结测试，不能继续宣称同一盲测。

运行目录中的 `budget.sqlite` 和 API 并发锁目录指向原累计目录。每步完成后写 checkpoint，重启只加载已提交步骤；完整任务重复调用不重新请求模型。失败或预算中止不会被分析器计为已完整完成。后台运行后按用户提醒检查，无需持续轮询。
