# V3 正式执行授权与范围

用户在离线阶段报告交付后明确要求：“暂时忽略20 美元预算上限，完成应该完成的实验，不要浪费就行”。因此，本批必需实验不再使用原 $20 项目上限；没有把此前建议的 $35 当作用户指定的新上限。

执行范围固定为：

- 开发预检：三个游戏各一个开发案例，只运行 V3，各最多 20 步，共 3 局。
- AO-FR-Hard：冻结的 89 个测试 family，STM、SimpleFailureRecovery、SCAR、SCARV2、SCARV3 全部实际执行，共 445 局，各最多 40 步，物理目标达到后统一停止。
- 长程：三个游戏、五种方法、每游戏一个新配对种子 909、每局最多 200 步，共 15 局。
- 不追加 RAG、额外种子、500 步、模块消融或重复完整实验。

继续使用原累计账本，不清零历史 $16.025308818。配置中的 `total_budget_usd: null` 必须同时存在对应的明确授权标记才能启用；原冻结 V1/V2 的 Provider、预算协议与历史结果不修改。逐请求保留 token、估算费用、失败请求与预留记录。

`scripts/finish_v3.py` 在服务器后台按开发、困难诊断、长程、统计分析、轨迹重放审计顺序执行。文件锁防止重复调度；完成的任务幂等跳过，未完成的任务从已提交 checkpoint 续跑。每次 API 请求最多三次尝试；连续三个任务执行故障停止分配新任务，阶段失败后不会继续下一阶段。费用限制解除不意味着无限重试或扩大研究范围。

整个运行代码与配置在启动时生成执行哈希；策略四个核心文件与困难数据仍保持原冻结哈希。并行度从 4 开始，根据完成情况升至最多 16，只在不同案例之间并行。固定动作上限、有限请求重试、异常停止和完整审计继续生效。

预算变更测试验证了“保留历史费用后允许本批超过 $20”，并验证“未记录明确授权时不能静默取消限额”。服务器全部 66 项测试通过。证据见 `results/v3/authorized_execution_tests_server.xml`。

启动前的《阶段报告》和离线交付清单保留为当时的记录，其中“等待预算”的状态已由本次授权解除。正式运行结束后应根据实际结果更新科研结论并发布实验数据，不能把“已启动”标成“已完成”。原始运行与后台状态在 `/root/scar_workspace/runtime_v3`。
