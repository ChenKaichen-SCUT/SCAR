# Stage16 行为一致性验证

验收通过：39/39 个 P3 历史检查点、4/4 个 S1 检查点和 4/4 个 P1 检查点的实际动作一致。所有 47 个所选状态均可严格恢复，没有剔除失败状态或用未来记录倒推。保存的 `chain_net` 三步短分支也一致。本地与服务器验收 JSON 完全相同。

## 检查点来源与比较范围

检查点取自 Stage15 `trajectories_P3/P0/P1.jsonl.gz`，包括原始公开观察、LLM 提案、执行动作和 `stage7_state_before`。35 个非首步检查点的事实表及 STM 来自原服务器前一步 memory；其控制器与原轨迹前置状态逐字段相同。12 个首步检查点只从当时已经公开的初始历史构造模型事实和 STM，不作决策、不启动环境；全部与保存的原请求 messages 和 fact_summary 对齐。

每个检查点独立恢复，运行旧、新控制器各一次 choose，然后各消费一次同一个保存反馈。比较预期实际动作、旧原始 structured 决策、完整 S1 核心状态、FIFO、重试/访问/批量记录、知识事件和更新时间、收尾条件与理由。Stage15 非决策审计字段的显式删除/更名见工程说明，除此之外不放宽状态比较。

还通过真实 Agent 类和记录回答 provider 比较 system/user messages 的完整字符串、事实摘要、STM 更新、Agent 反馈更新；验证 JSON 保存恢复后的下一动作。39 个 P3 状态覆盖原 10 个任务，历史成功与失败仅作为选点元数据，不计算本轮 R@40。
