# Stage16 工程整合说明

Stage16 以 `d747793d1a76a14004e43c8ad698b768afcf1f24` 为基础，把 S1＋P1＋P3 整理为默认工程入口。它是行为保持重构，不是新策略或新的性能实验。正式入口为 `scar_stage16.agent.make_agent(provider, ...)`，无需使用 Stage15 七配置批次脚本。

## 模块与原实现映射

| 新模块 | 职责 | 冻结来源 |
|---|---|---|
| `config.py` | 三个配置、模型与 STM 常量、40 步收尾时钟 | Stage15 参数 |
| `knowledge.py` | 公开知识表及模型事实摘要 | Stage15 P1 适配器，复用 Stage14 `Knowledge` |
| `controller.py` | S1 原执行器与 P3 最终目标收尾 | 直接继承 Stage10 `ResourceController`；提取 Stage15 四个收尾方法 |
| `state.py` | 八个只读公开状态查询 | 只读取控制器快照，不参与动作选择 |
| `agent.py` | 单次模型提案、事实摘要、STM、保存恢复 | Stage15 Agent 的同序操作及相同格式 |
| `migration.py` | 原始 S1／P1／P3 检查点的显式迁移 | 只迁移相应历史配置；拒绝配置错配 |
| `replay.py` | 有限历史状态及保存反馈验证 | 仅此验收工具调用 Stage15 参考实现 |
| `verify.py` | 冻结文件与历史文件哈希验收 | 不执行模型或游戏 |

生产模块不导入 `scar_stage15`。S1 配置直接创建原 `ResourceController` 和旧 `PublicFacts`；S1_P1 与默认配置才使用修复后的知识表。没有 P2/P4/P5/P6 配置入口，S2/S3 和其他 Stage7 开关保持关闭；检查点恢复也验证这些固定选项。

## 操作次序保持

每次行动依次进行：公开事实 `render(obs)` → 临时追加到原 system prompt → 原 STM `_act` 获取一次提案 → 恢复原 system prompt → 保存控制器前置状态 → 原 S1 `choose` → 按原 P3 顺序检查收尾 → 原语法校验 → 把 STM 最后一项替换为 `Proposed` 与 `Executed action` 格式。

收到真实反馈后，先执行 `controller.observe(before, action, after)`，再执行独立模型事实表的 `facts.observe`。P1 表仍先运行旧资源表观察，再用带来源的 Stage14 解析结果同步可行动配方；没有改动旧控制器内部的重复观察次数。知识去重、披露时点、FIFO、重试上下文、访问次数、批量样本和事实摘要顺序都参与逐状态比较。

P3 保留直接取得最终目标、最终制作后收取、一个局部直接依赖的收集或制作，以及原公共健康风险限制。`direct_finish` 的最终覆盖顺序保持不变：即使基础提案是批量存入最终物品，旧 P3 的直接拾取优先级仍可覆盖它。没有借此重构优化优先级。最终物品在地面上或制作成功都不等于已经持有足够目标。

## 有意删除的非决策实验记录

Stage15 的独立 S1 shadow 仅用于审计，在当前状态的深拷贝上运行，不向 P1/P3 决策提供输入；新生产控制器不再重复计算它。`intent15`、`continuation15`、`continuation_used15`、`continuation_selected15`、`protected15`、`loss15`、`history15` 是其他实验模块的记录，P1/P3 不读取它们作决策，正式入口不保留。

比较时明确进行以下结构映射：`knowledge15` → `knowledge`；`step15/risk15/health15` → `step16/risk16/health16`；P3 审计只保留原基础提案、P1 动作、最终动作、检查条件、模块选择和剩余行动数。`last_choice.resource_table` 中的知识键也同步更名。除此之外比较全部 S1 状态及完整知识事件，不能用忽略 FIFO 或条件记录的方式让验收通过。此处承诺的是行为和必要状态一致，不是原实验审计 JSON 的逐字节一致。

## 工程边界

`PublicRuleState` 构造时复制状态，所有查询返回脱离执行器的值。它不观察新反馈、不调用可变的 `admissible`，不对对象做相关性排序。`get_execution_status` 展示已知名义数量条件，但执行器不调用该接口改变决策，因此不启用 P2。

新 Agent 的 `initialize_episode` 接受已经公开的前缀观察、目标动作和公开目标；未来模块应读取 `agent.public_state`，执行真实行动后调用同一个 `observe_transition`。本轮没有假设管理器、未知规则学习器或新探索算法。
