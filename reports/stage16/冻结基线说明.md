# Stage16 冻结基线说明

验收结论：Stage16 可以作为后续未知规则游戏 Agent 研究的稳定工程基础。该结论基于本轮有限检查点、接口和单元测试；不声称对所有可能状态形式证明等价，也不声称新的成功率或泛化能力。

## 版本与配置

基础源码提交：`d747793d1a76a14004e43c8ad698b768afcf1f24`。Stage16 源码版本由包含本文件的发布提交及 `results/stage16/freeze.json` 中的 SHA-256 确定；发布文件集合由 `publication_manifest.json` 确定，避免在提交内容里写入无法自引用的自身提交 ID。

| 配置 | 控制器与知识 | 对应历史参考 |
|---|---|---|
| `S1` | 原 `ResourceController`、旧 `PublicFacts` | Stage15 P0／原 S1 |
| `S1_P1` | 原 S1、P1 公开知识，无 P3 干预 | Stage15 P1 |
| `S1_P1_P3`（默认） | 原 S1、P1、原 P3 收尾 | Stage15 P3 |

配置必须在创建新 Agent 时选择。保存状态的 schema_version、variant 与固定执行选项在恢复时校验；不能把已使用 P1 的状态改名为 S1 并声称等价。历史消融验收使用各方法自己的冻结前置状态和模型回答，未将 P3 的历史错当作 S1 历史。

## 固定参数

| 项目 | 冻结值 |
|---|---|
| 模型 | `deepseek-flash`，DeepSeek provider；thinking disabled |
| temperature / max_tokens | 0.7 / 768 |
| STM | 最后 5 项，含原观察、Proposed、Executed action |
| seed | 默认 42；历史检查点使用各自原 seed |
| 事实摘要 | 最多 48 条、6000 字符，沿用原类别轮转与排序 |
| 恢复目标后的行动预算 | 40，原 P3 剩余行动判断不变 |
| 局部收尾窗口 | 6 |
| 定向探索 / 每产物试探额度 | 18 / 4，沿用 S1 |
| 制作批量 | 原 S1 实现及公开上下文样本，最多请求 4；不固定成 craft 1 或 craft 2 |
| Stage7 开关 | 仅 `retry_context_fix=True` |
| S2 / S3 | 关闭 |
| 额外模型调用 | 0 |
| embedding 元数据 | `Qwen/Qwen3-Embedding-0.6B`，revision `97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3`；本 STM 不加载 embedding |

Agent 继续接收外部 provider 的 `generate(user_prompt, system_prompt)`。模型请求参数是 provider 合同的一部分，注入的真实 provider 须遵守上述值；Agent 的 cfg 也保留相同参数。本轮只注入保存回答的 `RecordedProvider`，未创建远程 API 客户端。`configs/stage16_baseline.json` 记录该合同。

外部 AgentOdyssey 仍固定 `248430692a9d4a61d38c6c03ab2126287faaf450`。初始游戏提示、动作提示及目标追加格式沿用该版本和原 Agent；具体实例见 `prompt_contract.json`，47 个检查点的完整 system/user messages 均与保存请求逐字比较。

## 验收与扩展约束

- 39 个 P3 状态覆盖原 10 个任务及历史成功、失败情况，实际动作全部一致。
- 另外 4 个 S1 和 4 个 P1 状态使用各自原始历史，动作与必要状态全部一致。
- 保存的 `chain_net` 原生三步分支逐步选择、反馈更新一致，没有启动引擎。
- 本地和服务器各 279 项单元测试通过，其中 80 项为 Stage16 新测试；相关旧测试 199 项。
- JSON 恢复、事实摘要、STM、初始公开历史装载、八接口只读性、禁止未来证据、配置错配等检查通过。
- 2519 个基础版本已跟踪历史文件未改动；服务器旧实验账本及任务输出哈希保持不变。

旧实验的非决策辅助审计字段被删除或更名，映射见《工程整合说明》。这不是所有原始 JSON 字段逐字节相同；可影响本配置决策的状态、知识、FIFO、条件和收尾理由均严格比较。

未来未知规则模块应另建目录／配置，在此冻结版本之上接入真实观察。任何基础 S1/P1/P3 变更均需明确作为基线版本变化记录，不能静默调整以提高新算法分数。Stage16 完成后停止，不自动启动该研发或任何新数据集实验。
