# Stage16 公开规则状态接口

接口版本为 1。使用 `view = agent.public_state` 或 `PublicRuleState(controller)` 获取当前不可回写的快照。后续真实观察到达后应重新取快照；旧快照不会自动获得未来知识。查询返回普通、可 JSON 序列化的字典／列表，修改返回值不会改变快照或执行器。

## 知识语义

| 状态 | 含义 |
|---|---|
| `KNOWN` | 该字段有当前已保存的真实公开证据支持 |
| `UNKNOWN` | 尚未披露或当前不能确定；不表示不存在或无法制作 |
| `CONFLICTED` | 公开证据冲突，保留证据，但不作为可行动配方 |

配方整体 `status=KNOWN` 表示存在公开记录，可能只有工作台失败反馈；各字段仍独立标注确定性。已知工作台仅是必要条件的已知子集，绝不推断其完整性。名义配方数量不代表线性批量消耗；`station_completeness`、`batch_consumption` 保持 UNKNOWN，因此当前解析能力下 `complete` 保守为 false。

来自 `P3-chain_net-36` 的真实公开记录节选：

```json
{
  "product": "chain_net",
  "status": "KNOWN",
  "materials": {"status": "KNOWN", "value": ["iron_bar", "sinew_cord"]},
  "quantities": {"status": "KNOWN", "value": {"iron_bar": 3.0, "sinew_cord": 2.0}},
  "stations": {"status": "KNOWN", "value": ["crucible", "war_bench"]},
  "first_observed_step": 10,
  "first_relation_step": 29,
  "first_quantity_step": 30,
  "complete": false,
  "missing_conditions": ["station_completeness", "batch_consumption"],
  "as_of_step": 46
}
```

这里 `first_observed_step=10` 是最早工作台失败证据；材料关系和数量分别在公开 step 29、30 披露。step 46 为环境公开时间，Stage16 的 `step16=36` 是恢复目标开始后的行动数，二者不能混用。`source_action`、`raw_evidence` 保存首次证据；完整后续来源、数量更新与冲突见 `get_rule_evidence`。

完整八接口输出保存在 `results/stage16/interface_example.json`。

## 查询契约

| 方法 | 返回及边界 |
|---|---|
| `get_recipe(item)` | 产物、材料与数量、工作台、首次记录/关系/数量时间、原始证据及动作、证据 ID、完整性、未知条件、来源模式、截止观察时间 |
| `get_known_dependencies(item)` | 已确认的直接依赖。UNKNOWN／CONFLICTED 返回空依赖并保留状态，不能把空列表解读为“无需材料” |
| `get_missing_knowledge(goal=None)` | 在已公开依赖图上遍历的缺口，包含未知叶节点，去重防环；不从名称推断隐藏依赖 |
| `get_available_materials()` | 当前手持/装备/地面计数及确定性；公开持有量下界；可接触容器的历史计数、时间和当前不确定性 |
| `get_rule_evidence(item)` | 全部真实公开事件、来源动作、原文、首次关系/数量时间及冲突标记；S1 缺少完整来源时明确 `provenance_available=false` |
| `get_execution_status(item)` | 原 S1 三值条件结果、公开阻碍、名义材料数量条件、未知条件和允许重试与否；不保证实际制作成功，也不改变策略 |
| `get_goal_status()` | 公开记账支持的持有量、所需数量、完成状态、直接取得机会及执行条件；不把地面目标或历史产量计入持有完成 |
| `get_uninspected_objects()` | 曾在场地、手持、装备或容器内观察且未检查的对象及来源时间；保留记录顺序，不计算相关性或行动排名 |

持有量的 `complete_public_accounting` 只表示公开手持、装备及已知携带容器计数完整，不能排除未观察到的外生变化。容器的历史计数与当前真实内容分开标注。`get_goal_status.complete` 沿用原 P3 的公开持有记账标准，不是对隐藏世界的额外验证；地面物品绝不直接算作完成。

S1 查询仅展示旧解析器已有记录，标记 `source_mode=S1_legacy_record`，不补跑 P1，也不把旧观测消耗平均值提升为名义配方数量。S1_P1／S1_P1_P3 才提供 P1 的完整来源记录。

## 更新与扩展

真实反馈仍通过 `agent.observe_transition(before, action, after)` 单向进入知识和执行状态。调用方必须提供真实公开观察，不能把模型生成的仿真反馈当作环境证据。底层 `Knowledge.observe(..., source_kind='model_response')` 会拒绝将模型内容作为规则；`cutoff` 拒绝未来观察，但不能凭文本本身鉴别伪造来源。

接口没有修改配方、合并模型猜测或提交隐藏规则的入口。以后未知规则模块应独立实现，通过这些查询读取缺口，通过真实行动取得反馈，继续交由同一执行器观察。不要改动冻结的基础优先级、阈值或批量逻辑。
