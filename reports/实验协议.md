# 正式实验协议

本协议在正式 AO-FR 数据生成和长期测试之前冻结。正式测试开始后不再根据成绩调整 SCAR、提示词或基线。开发阶段修复及失败均保留 Git 历史与服务器日志。

## 研究问题与公平性

完整 SCAR 是否在真实恢复、主线奖励及错误拦截方面优于官方 STM、CPU VanillaRAG、LongContext 和简单失败恢复？核算全部额外推理，允许 PARTIAL 或 NO-GO，不安排消融或参数搜索。所有方法用同一 Flash 非思考设置、公开文本和动作空间。引擎副本、世界状态、可达性见证不能传给策略。

## 阶段与预算

1. 开发种子 7：三个游戏、五种方法，先 20 步 smoke，再 120 步 pilot，不作正式性能证据。
2. 冻结后用官方 STM 采集新种子 404/505 的 120 步自然轨迹。诊断开发集来自种子 7；测试集来自 404/505，排除已见 tutorial 状态。条件释放变体与母案例共享 family/split。
3. AO-FR：相同快照、相同已观察历史，每种方法最多 20 个真实步骤。可达性在策略运行前通过动作见证和两次独立重放确认。限定搜索没有见证的案例为“未验证”，排除恢复分母，不声称不可恢复。
4. 长期实验：三个游戏 × 种子 101/202/303 × 五个方法，每局 200 步上限，共 45 任务。
5. 成本实验：另外运行同样的 45 配对任务，每局 API 上限 $0.15 且最多 200 步，请求前执行额度检查，不以事后截断曲线冒充实际实验。

smoke/pilot 累计上限 $3；所有阶段共用累计 $20 上限。按 UTF-8 字节数、输出上限、固定高峰单价预留费用，SQLite 事务防止并发超额。超时且计费未知的请求保守保留额度。单局额度耗尽为预定义停止；总预算停止与 API/环境故障分别报告。保持已完成任务与原始轨迹，禁止覆盖。

## 真值与指标

- 主指标：引擎主线 quest 奖励、Recovery@10/@20、FBR。
- 官方 IAR/RIAR 使用 `step_invalid_action`；语义失败率另列，不混用两种口径。
- 语义拒绝与 FBR 在独立副本执行实际动作规则，捕获动作阶段反馈，排除后续 NPC/tutorial 文本干扰。仍依赖显式拒绝文本，必须报告误标风险。
- RIAR：相同规范化动作、相同可观察状态摘要下再次拒绝次数 / 实际环境步数。不声称识别所有语义等价动作。
- Recovery 必须满足预定义真实状态目标，例如到达目标区域或新增目标物品；不再重复失败不算恢复。达到同一目标的替代行动可计入。
- B 类型另列条件解除后成功重试原动作的步数；D 为前置动作恢复链，不能声称已经覆盖不同地图路线。
- 冻结 CRA：只使用开发种子学到的规则，对测试状态评分而不更新规则。在线每 10 步审计属于额外探索性数据。
- Completion 直接取引擎主线完成触发的终止标志，不由奖励猜测。
- 每步保存初始候选、修复候选、最终动作、反馈、奖励与全部请求。信息获取、重试、修复均计步/计费。

## 统计与结论

报告均值、中位数、游戏/种子配对差值、10,000 次配对 Bootstrap 95% 区间。诊断按 family 聚类；状态变体不得虚增独立样本。分别报告各游戏、已完成及未完成任务和原因。每游戏只有三个测试种子，应明确不确定性。

GO 要求恢复、误拦截控制及至少部分主线收益提供证据，且优于简单强基线；局部收益归 PARTIAL；没有超过简单恢复、没有任务收益或误拦截退化时当前版本归 NO-GO。样本不足时直说不能判断，禁止把未运行的实验写成负面结果。

本实验使用 DeepSeek、200 步，与官方 Challenge 的限定 Qwen 模型和 500 步规则不同，不申报官方排名。
