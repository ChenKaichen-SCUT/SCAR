## 修改内容

第一轮出现大量旧计划接管合法候选、状态变化后强制重试过早、队列中旧动作格式未重新校验等问题。本轮只修改完整 SCAR 的动作修复控制：

1. 基础策略仍用官方 STM 的相同 prompt 产生候选，再检查该候选。
2. 仅高置信条件失败规则命中或公开动作签名不合法时介入；最近失败本身不触发修复。
3. 解除条件或冷却后允许基础策略主动提出的重试，不强制执行旧目标。
4. 队列只用于当前同一受阻目标；每次执行前重新检查语法、位置、时效和失败规则。
5. 没有合法修复时，合法原候选只作显式验证；原候选格式不合法且修复失败则记录错误并停止，不转换成无声等待。

失败诊断、条件记忆、在线规则更新及保存恢复仍来自冻结的第一版；四模块完整保留。没有使用隐藏环境状态帮助策略决策。

## 可比性与限制

首次新版 API 请求之前，已冻结 `results/v2/freeze.json`。第一轮 `scar/` 核心哈希不变，新策略哈希单独保存。

复用的是完全相同的游戏版本、模型名称、非思考模式、温度、输出上限、基础观察与评分口径。种子 101 的快照逐字节复制，诊断使用相同冻结快照、历史和目标；清单中所有 318 条历史任务配置均已核验。运行结束还将比较实际初始环境摘要并抽样精确重放。

这是**回归比较**，不是新的未见测试。修改依据来自第一轮已观察的结果。只有每游戏一个随机种子，且远程模型无法保证请求级确定性；复用基线也不能排除跨时段服务变化。诊断按 family 配对 Bootstrap，长程同时呈现每游戏原始结果及三组配对差，避免以小样本均值推断整体优越性。

诊断集四类覆盖不足、C 类型缺失及自然/合成来源说明沿用第一轮报告。独立 CRA 不冒充本轮新学规则的验证；另行报告新版在线探索性规则审计。

## 执行与复现

服务器工作目录 `/root/scar_workspace/project`；新版原始数据 `/root/scar_workspace/runtime_v2`；历史数据 `/root/scar_workspace/runtime`。下载的官方代码和模型继续保留在仓库外。

```bash
cd /root/scar_workspace/project
export PYTHONHASHSEED=0 OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1
export HF_HUB_OFFLINE=1
export AGENTODYSSEY_ROOT=/root/scar_workspace/dependencies/agentodyssey
PY=/root/scar_workspace/venv/bin/python
"$PY" -m scar_v2.run --stage freeze \
  --runtime /root/scar_workspace/runtime_v2 \
  --historical-runtime /root/scar_workspace/runtime
"$PY" scripts/finish_v2.py \
  --runtime /root/scar_workspace/runtime_v2 \
  --historical-runtime /root/scar_workspace/runtime \
  --key-file /secure/path/to/key
```

上述复用依赖服务器的历史快照与轨迹。单独克隆 GitHub 并不包含这些大型文件；精确审计应在保留原数据的服务器执行。不要删除或覆盖历史运行目录。

仅重算结果及应用已审阅的结论，无需调用 API：

```bash
"$PY" -m scar_v2.analyze \
  --runtime /root/scar_workspace/runtime_v2 \
  --historical-runtime /root/scar_workspace/runtime
"$PY" scripts/review_v2.py --runtime /root/scar_workspace/runtime_v2
```

结论复核保存在 `results/v2/scientific_review.json`，绑定新版结果及历史比较清单的哈希，防止重新实验后静默沿用旧结论。后验门控审计和成败变化案例均明确为结果分析，不修改已冻结策略。
