## 无 API 的复现

`results/sequence/dataset/initial_states/` 包含本次生成的 35 个初始物理快照，没有策略或 API 客户端。只加载已核验 hash 的本仓库可信 pickle；不要加载来源不明的 pickle。

重放一个初始状态及其恢复见证：

```bash
python -m scar_sequence.replay --case sequence-3d1ba557c7dabb5d
```

把全部状态恢复到自己的独立工作目录，默认不调用模型：

```bash
python -m scar_sequence.reproduce --runtime /path/to/new_sequence_runtime
python -m pytest tests/test_sequence.py -q
```

所有生成规则、初始改动、共同公开历史、目标、见证和 hash 均在 `results/sequence/dataset/`。各方法压缩轨迹包含每一步实际反馈、基础模型响应、提议/实际动作、结构化状态和独立物理评估。`requests_*.jsonl.gz` 提供 token、费用与完整请求/响应审计；不包含请求头或密钥。

已有服务器完整运行目录时，可重算统计、重新重放并生成报告：

```bash
python -m scar_sequence.resource_audit --runtime /root/scar_workspace/runtime_sequence
python -m scar_sequence.analyze --runtime /root/scar_workspace/runtime_sequence
python -m scar_sequence.verify --runtime /root/scar_workspace/runtime_sequence
python -m scar_sequence.mechanism_cases --runtime /root/scar_workspace/runtime_sequence
python -m scar_sequence.report
```

`resource_audit` 是明确披露的事后计数校正：原运行时字段用配方名义小数扣除消耗，但引擎对剩余数量向下取整。独立执行原始动作规则，把实际动作消耗与随后环境销毁分开；不改变原轨迹或任何恢复成绩。

全量运行时检查点保存在服务器。仓库中的压缩初始状态和逐步动作也足以重新执行完整轨迹；与原模型再次采样属于不同复现问题。

## 明确启动新的付费闭环

只有下面带 `--run-closed-loop` 的命令会调用模型。应使用新的运行目录，保留此前结果：

```bash
python -m scar_sequence.reproduce --runtime /path/to/new_sequence_runtime \
  --run-closed-loop --key /private/path/to/deepseek-key --workers 12
```

该命令核对冻结数据与策略 hash，只映射初始快照路径；五种方法、模型参数、40 步上限与新增 $12 自动保护保持一致。初始物理状态可以精确重放，远端模型不提供可保证一致的采样随机种子，因此重复调用不保证复现相同动作。
