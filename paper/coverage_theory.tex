\begin{abstract}
An LLM game agent must decide which uncertain action rules to test, whether a
test fits the remaining task budget, and when its outcome may constrain future
plans. We formalize these three decisions using finite competing action models,
observation-contingent local policies, and context-scoped evidence. The implemented
mechanism lifts surviving compiled models back to joint semantic profiles,
filters later planning problems, and turns contradicted proposals into explicit
enabling conditions. We prove conditional local
completion, action-budget accounting, and sound reuse under explicit realizability
and stationarity assumptions. These are correctness statements for the mechanism,
not a claim of global game safety, optimal game play, or novel hypothesis
elimination. A selected real-game replay demonstrates three avoided failures
after one acquisition action; a single matched-budget LLM continuation improves
the score by one without completing the game. These are development results,
not broad superiority. The earlier
candidate-coverage supplement is archived separately and is not used to explain
the reported game scores.
\end{abstract}

\section{Problem definition and the role of the LLM}
A game exposes a public history $h_t=(o_0,a_0,o_1,\ldots,a_{t-1},o_t)$,
a remaining environment-action budget $B_t$, and an external task success signal
or task-progress measure. The experimental objective is progress or completion
within this budget. It is not identification of every hidden game rule.

From this history, the language-based agent proposes a method milestone $g$,
such as \emph{newly craft and hold a sword}. Grounding produces a finite local
problem only when the necessary public information is available. A milestone is
not assumed equivalent to the natural-language quest: obtaining ingredients is
a precondition, not an extra terminal requirement. The current implementation
uses V6/LLM target proposals and a hand-specified family of quantity/access rules;
it does not learn arbitrary action schemas from LLM text.

\begin{definition}[Local query]
A grounded query is $Q=(X,A,\Theta,b_0,g,K,H)$, where $X$ is a finite state
space, $A$ a finite command set, $\Theta$ a finite set of joint semantic profiles,
$b_0=\{(\theta,x_\theta):\theta\in\Theta_0\}$ the current candidate belief,
$g$ the local terminal predicate, $K$ the modeled state constraints, and
$H\leq B_t$ the local action budget. A profile specifies deterministic transitions
$T_\theta(x,a)$ and public observations $O_\theta(x,a,T_\theta(x,a))$.
Each issued command costs one environment action, including a failed command.
\end{definition}
An unavailable command is represented by its modeled failure transition when the
environment permits issuing it. A policy must therefore account for failures;
syntactic command availability is not success. Resources can be consumed,
produced, moved, and constrained by capacity. The old resource-only-decreasing
coverage model is not imposed here.

In the implemented domain, $x$ records location, elapsed actions, craft-event
bits, and integer milli-unit quantities in the hand, attached bag, and floor.
$K$ checks nonnegative counts, hand/bag capacities and explicitly declared
protected totals. The automatic adapter leaves protected totals empty: it does
not certify resources needed by unrelated quests. $g$ checks the new craft event
and current possession. Bag contents are observable only through the modeled
inspection operation; model IDs never appear in observations.

For ingredient coefficient $c$ and integer batch $q$, the quantity rules are
\[
 d_{\rm exact}(c,q)=cq,\quad
 d_{\rm batch}(c,q)=1000\lceil cq/1000\rceil,\quad
 d_{\rm output}(c,q)=1000q\lceil c/1000\rceil.
\]
Access rules permit hand, hand plus bag, hand plus floor, or all three. A profile
is a \emph{pair} of quantity and access rules; retaining the two marginals would
lose correlations established by an observation. Consumption priority, floor
output, fixed loads, station sufficiency, material-preserving failure and absence
of ambient effects remain assumptions of this family.

For a fresh observation $o$, update by
\begin{equation}\label{eq:update}
 b[a,o]=\{(\theta,T_\theta(x,a)):(\theta,x)\in b,\
 O_\theta(x,a,T_\theta(x,a))=o\}.
\end{equation}
An empty actual successor is model mismatch, not evidence of task impossibility.
An incomplete observation is not filled in with a preferred model prediction.

\section{Which verification actions are permitted?}
\subsection{Freeze the original obligations}
At query admission fix $b_0,H,g,K$. In strong mode all profiles must reach $g$.
In opportunity mode let $E_0$ contain only profiles with a proved absence of a
$K$-respecting goal trajectory within the \emph{original} horizon $H$. Let
$R_0=\supp(b_0)\setminus E_0$. An unresolved individual search remains in $R_0$.
Both sets are frozen throughout this trial. No new exemption is granted after
an action has consumed material or time. Exempt worlds still constrain $K$ and
observations. If $R_0$ is empty, the controller does not select a verification
trial on the basis of a vacuous completion requirement.

An exemption is relative to this fragment and horizon. Unmodeled upstream
recipes, remote resources, or another method may still solve the full game.
Exemption is neither falsification of a profile nor global infeasibility.

\begin{definition}[Admissible verification prefix]\label{def:admit}
Let $p$ be a command prefix whose public observations first split the surviving
profiles at its last action, and let $k=|p|$. It is admissible when:
\begin{enumerate}[label=(\roman*)]
\item every intermediate state along every modeled prefix execution satisfies $K$;
\item for each resulting observation leaf $o$, there is a \emph{single}
observation-based suffix policy $\pi_o$ that satisfies $K$ in every world in
$b_o$, and reaches $g$ for every surviving profile in $R_0$;
\item $k+\max_o\cost(\pi_o,b_o)\leq H$.
\end{enumerate}
The cost of a policy is the maximum path length over all its candidate worlds,
including exempt worlds. A leaf with only exempt worlds may stop without $g$,
and must be reported as such.
\end{definition}
The central quantifiers are $\forall o\ \exists\pi_o\ \forall\theta\in b_o$.
The weaker $\forall\theta\ \exists\pi_\theta$ permits an omniscient choice and
does not certify a usable experiment. The implementation searches bounded
nonbranching preparations up to the first split; it does not enumerate all
possible experimental policies.

\begin{theorem}[Conditional local completion]\label{thm:local}
Assume (a) the true grounded world belongs to $b_0$; (b) its transitions and
observations agree with its candidate throughout execution; (c) the grounded
state, $g$, and $K$ have their declared meanings; and (d) the certified commands
are executed without unmodeled interventions. Executing an admissible prefix
and its observed suffix maintains $K$ and terminates within $H$. If the true
profile belongs to $R_0$, termination satisfies $g$.
\end{theorem}
\begin{proof}
Initially the true pair belongs to $b_0$. By (b) and (d), each issued command
produces its modeled successor and observation. Equation~\eqref{eq:update}
therefore retains that pair, inductively. Condition (i) covers the prefix;
condition (ii) covers all suffix states and its required terminal goal. The
observed leaf determines one common policy, so no hidden identity is needed.
Condition (iii) bounds the entire path. An exempt true profile is covered by the
constraint and cost argument, but not by the goal conclusion.
\end{proof}
The theorem is deliberately local and conditional. In the actual game,
\texttt{MODEL\_MISMATCH} and \texttt{OBSERVATION\_GAP} stop further certificate
use. Detection after an action cannot undo that action or prove it was safe.
The fallback LLM policy does not inherit this local theorem.

\section{Why spend the action budget on verification?}
\subsection{An implemented budget guard, not a value-of-information claim}
Let $\pi_{\rm ref}$ be a replay-verified common policy for the same query and
frozen obligations, with worst path cost $C_{\rm ref}$. A proposed experiment
with certified suffixes has
\begin{equation}\label{eq:cost}
 U(p)=|p|+\max_o\cost(\pi_o,b_o).
\end{equation}
The current selector requires
\begin{equation}\label{eq:allowance}
 U(p)\leq H,\qquad U(p)\leq C_{\rm ref}+\Delta
\end{equation}
when a reference has been found. $\Delta=0$ in the game runs. When no reference
has been found, only the horizon and admissibility tests apply. Failure to find
a reference within a computation budget is not proof that none exists.

\begin{proposition}[Budget accounting]\label{prop:budget}
Under Theorem~\ref{thm:local}'s assumptions, an admitted experiment consumes at
most $U(p)$ environment actions. If a reference exists, its worst-cost overhead
is at most the declared allowance in the sense of~\eqref{eq:allowance}.
\end{proposition}
\begin{proof}
Every execution consists of the $|p|$ charged prefix commands and one verified
suffix path. The latter is no longer than its leaf's verified maximum. Maximizing
proves~\eqref{eq:cost}; the selector explicitly checks~\eqref{eq:allowance}.
\end{proof}
$C_{\rm ref}$ is an upper bound from an existing witness, not an optimal cost or
a lower bound. This proposition does not establish pointwise dominance over
$\pi_{\rm ref}$, improvement in expected game score, wall time, or API cost.
The selector ranks admissible experiments by worst total cost, remaining model
count, excess production, and prefix length. The information tie-break is a
heuristic: cardinality alone is not the benefit being optimized in the game.

\subsection{When information can change a later decision}
For a \emph{fixed} query state, horizon and frozen obligations, let $V_R(b)$ be
the optimal worst action cost of a common policy satisfying those obligations,
or infinity if none exists. Restricting the belief also restricts required
profiles to $R\cap\supp(b)$; it never creates a new exemption for a retained one.

\begin{proposition}[Decision value under sound elimination]\label{prop:monotone}
If $b'\subseteq b$ consists of the same retained profile--state pairs, then
$V_R(b')\leq V_R(b)$. The inequality need not be strict. This statement does not
compare the state before a resource-consuming experiment with the state after it.
\end{proposition}
\begin{proof}
Any feasible policy for $b$ can be restricted to observation paths reachable from
$b'$. Its constraints and terminal obligations continue to hold and its maximum
path length cannot increase. Taking minima proves the result, including the
case $V_R(b)=\infty$. A costly experiment changes states and remaining horizon,
so the subset premise does not hold for that comparison.
\end{proof}
A finite search budget may return a worse witness despite a smaller exact
optimum; the proposition is about $V_R$, not every bounded solver run.

\begin{example}[A decision-relevant and a decision-irrelevant distinction]
A blade needs one unit of ore, available only in an attached bag. The rules are
hand-only and hand-plus-bag. Without distinguishing them, the common policy is
\emph{take out ore; craft; pick up blade}, costing three actions. Sound prior
evidence for hand-plus-bag permits \emph{craft; pick up}, costing two, in the
same later state. If the ore is already in hand, both rules permit the same
two-action policy: identifying access gives no action saving there.

Testing \emph{craft} in the bag-only state succeeds under one rule, but under
hand-only it fails and still requires the three-action policy. Its worst cost
is four, so a zero-allowance guard rejects this test against a three-action
reference. Information is not automatically worth its acquisition cost.
\end{example}

\subsection{A computable prospective comparison with a fixed reference}
Let $\pi_0$ be a verified reference policy and $\pi_p$ a verified test-prefix
and continuation policy, starting from the same query with the same frozen
success obligations. Replay both under every profile, including success-exempt
profiles, and define
\[
 d_\theta(p)=C_{\pi_0}(\theta)-C_{\pi_p}(\theta),\qquad
 L(p)=\min_{\theta\in\Theta_0}d_\theta(p).
\]
All prefix, failure, inspection and continuation actions enter these costs.
This comparison is computed before executing the proposed test.
\begin{proposition}[Reference-relative nondegradation]\label{prop:profilevalue}
Under faithful local semantics and true-profile inclusion, $L(p)\geq0$ implies
that $\pi_p$ costs no more actions than $\pi_0$ under the true profile.
If $L(p)>0$, it saves at least $L(p)$ under every candidate. Both statements
retain the original conditional scope of the policies' success obligations.
\end{proposition}
\begin{proof}
For the true profile $\theta^*$, $d_{\theta^*}(p)\geq L(p)$ by definition.
The complete replay costs start at the same state, so their difference is a
pathwise comparison. Policy verification separately establishes obligations,
constraints and budget. No optimality of $\pi_0$ is assumed or concluded.
\end{proof}
For $N$ profiles and depth at most $H$, the additional replay costs $O(NH)$
transition lookups per comparison, after policy construction. This does not
bound grounding or search. Behavioral aliases have identical costs in this
compilation and may share a replay without losing profile correlations.

Worst-case costs alone are insufficient: vectors $(1,4)$ and $(3,4)$ have the
same maximum but the second loses two actions under the first profile. This is
an arithmetic counterexample, not itself a game instance. V11 rejects a test
with $L(p)<0$ when a verified reference exists. Without such a reference it
reports \texttt{UNKNOWN} value and may use the original horizon/opportunity
certificate, without claiming nondegradation. Zero does not establish strictly
positive information value. The reference can itself use observations; this
is not globally optimal value-of-information estimation. The conservative gate
may reject a test whose future reuse would justify a present loss.

\subsection{A sufficient amortization condition, with explicit limits}
The following is a proposed analysis tool, not a deployed test-selection rule.
It states what must be estimated before justifying a positive allowance by
future reuse. Suppose a finite sequence of future query states and budgets is
specified. For each true profile, both strategies reach the \emph{same} next
query state, or any additional routing/replenishment cost is included explicitly.
All guards remain valid; policies and their path costs can be replayed for every
profile. These assumptions are not established for arbitrary game progression.

For profile $\theta$, let $C_{0}^{\rm test}(\theta)$ and
$C_{0}^{\rm ref}(\theta)$ be acquisition-episode costs including completion, and
$C_j^{\rm reuse}(\theta),C_j^{\rm ref}(\theta)$ later episode costs.
Set
\[
 e=\max_{\theta}\bigl(C_0^{\rm test}(\theta)-C_0^{\rm ref}(\theta)\bigr),
 \qquad
 s_j=\min_{\theta}\bigl(C_j^{\rm ref}(\theta)-C_j^{\rm reuse}(\theta)\bigr).
\]
These are pathwise comparisons with verified \emph{specified policies}, not
differences of unrelated upper and lower bounds.
\begin{proposition}[Sufficient amortization]\label{prop:amortize}
Under the stated matched-query assumptions, if $e\leq\sum_{j=1}^k s_j$, the
test-and-reuse strategy costs no more than the reference strategy for any
candidate profile across these episodes. Each episode must separately satisfy
its actual remaining budget and constraints.
\end{proposition}
\begin{proof}
For each $\theta$, subtract total reference cost from total test-and-reuse cost.
The acquisition difference is at most $e$ and each later difference is at most
$-s_j$. Their sum is at most $e-\sum_j s_j\leq0$. Matching boundary states (or
charging all differing boundary costs) makes this sum describe the two actual
strategies. A total-cost inequality alone does not ensure an intermediate
budget or resource constraint, which is why these require separate checks.
\end{proof}
The condition may fail: the hand-only branch in the example saves nothing in
later episodes. Without a justified distribution or guaranteed revisits, a
successful-branch saving cannot pay for a failed-branch loss. Current software
therefore uses the explicit local allowance, not a claimed estimate of future
information value. A future empirical estimator must report prediction error
and acquisition costs rather than treating every elimination as a benefit.

\section{When may learned evidence be reused?}
\subsection{Context-scoped raw profiles}
A context guard $\kappa(Q)$ describes the assumptions under which semantic
parameters are treated as stationary. The implemented guard includes recipe
identity and quantities, station evidence, location/routes, item vocabulary,
equipment and bag identity, capacities/background loads, semantics version and
raw profile universe. It excludes current inventory quantities, public-history
length and offered batch sizes. These excluded fields are re-grounded for each
new query; they are not copied from an old state. Changes to included fields
prevent cross-context filtering.

Equality of these recorded fields does \emph{not} prove guard adequacy. Time,
level, buffs or other unmodeled variables may affect a craft. In particular an
observed evening bonus in Mark falls outside the current family. A valid reuse
theorem requires that any excluded variable either is modeled as state or does
not change the shared semantic parameters. The current game system has not
established that assumption generally.

\begin{definition}[Evidence ledger]
For a context $\kappa$ and validity epoch $e$, let $\Theta_\kappa$ be its raw
joint profile universe and $S_{\kappa,e}$ its current survivors, initially
$\Theta_\kappa$. A matched public transition $i$ defines compatible raw profiles
$C_i$ by replay against the pre-observation belief. Update
\begin{equation}\label{eq:ledger}
 S_{\kappa,e}\leftarrow S_{\kappa,e}\cap C_i.
\end{equation}
Each update stores the action, observation digest, local compilation fingerprint,
context/epoch, and eliminated joint profiles. Search infeasibility and unresolved
search are not transition evidence and cannot enter this update.
\end{definition}
A new query with the same context compiles only its profiles in $S_{\kappa,e}$.
Thus evidence changes available future policy branches and the selected action,
not merely a textual memory entry. The implementation supports one recipe per
persistent query; it does not independently factor multi-recipe correlations.

\subsection{Aliases must survive changing action sets}
The compiler may collapse profiles with identical behavior in a query. For
example, the two rounding rules coincide when only batches of size one are
available. Names such as \texttt{m0} are local to that compilation, not stable
semantic identities. Let $\alpha_Q(m)$ be all raw aliases represented by model
$m$. For surviving compiled models $M_i$, use
\[
 C_i=\bigcup_{m\in M_i}\alpha_Q(m)
\]
before applying~\eqref{eq:ledger}. Filter raw profiles \emph{before} quotienting
the next query; its different batch set may split an old equivalence class.

\begin{lemma}[Alias lifting]\label{lem:alias}
Suppose a compiled class represents exactly the same transitions and observations
as all its raw aliases on every action/state reachable within the current
query's horizon. Retaining the union of aliases of matched classes does not
eliminate a raw profile consistent with that query's actual observations.
\end{lemma}
\begin{proof}
Any consistent raw profile belongs to a class making the same predictions along
the actual path. That class survives every matching observation. Its entire
alias set is retained, including the profile. No choice of a single canonical
representative is transferred to a later, possibly finer query.
\end{proof}
For no attached bag, bag-inclusive and bag-exclusive access modes may collapse;
the aliases still preserve their unresolved distinction. For an integer-unit
recipe all quantity rules coincide; for noninteger coefficients and unit batches,
only the two ceiling rules coincide. These are the compiler's declared reductions.

\begin{theorem}[Guarded reuse]\label{thm:reuse}
Assume a fixed epoch has a true raw profile $\theta^*\in\Theta_\kappa$; all
recorded transitions are faithfully observed and modeled under that profile;
the guard is adequate to keep these semantic parameters valid in every query
using the epoch; and the compiler satisfies Lemma~\ref{lem:alias}. Then
$\theta^*\in S_{\kappa,e}$ after every valid update. Filtering a later matching
query by $S_{\kappa,e}$ therefore does not remove its true profile. With fresh
correct grounding, Theorem~\ref{thm:local} applies to a newly verified policy in
that filtered query.
\end{theorem}
\begin{proof}
The initial survivor set includes $\theta^*$. At each matched observation,
correct transitions and observations keep its compiled class alive. Alias
lifting places $\theta^*$ in $C_i$; intersection preserves it. Induction proves
the first statement. Guard adequacy transfers the same parameter interpretation
to a new query, whose states and constraints are re-grounded. Filtering happens
before recompilation, so the true profile remains represented even if the new
quotient differs. The new certificate, not the old action sequence, supplies
its own completion and budget argument.
\end{proof}
Observations may repeatedly fail to distinguish surviving profiles. The theorem
does not imply identification, fewer LLM calls, or a bound on total game failures.
For a fixed finite nonempty universe, there are at most $|\Theta_\kappa|-1$
strict eliminations in a realizable epoch. This elementary finite-elimination
fact is not a sample-complexity or novelty claim. Changing contexts, expanding
the family and opening new epochs void any across-run version of that count.

\subsection{Invalidation and recovery}
All-model mismatch, incomplete modeled feedback, or incompatible checkpoint
execution revokes the epoch's exclusions; the controller cancels its current
continuation. The ledger keeps the audit, restores the unfiltered family for a
fresh epoch, and makes no claim that the family is now correct. Different
contexts use separate ledgers. Model-family expansion changes the universe and
requires new validation. Restoring a checkpoint preserves the frozen filter,
epoch, spent actions, original exemptions and feedback replay; it must reproduce
the policy fingerprint before continuing.

Revocation is conservative: combat can revoke evidence even when the quantity
rule did not actually change. Conversely a hidden change that continues matching
some false profiles can remain undetected. Neither clearing a ledger nor a
successful subsequent action repairs a missing true model. The present mechanism
is exact elimination under assumptions, not probabilistic belief revision.

\section{From evidence to persistent method revision}
\subsection{What a cheap rejection actually establishes}
For a guarded query, let $S$ be surviving joint profiles and $\Theta$ the
unfiltered universe. V10/V11 review a craft without new planning search when
(i) some profile in $\Theta$ predicts success, (ii) every profile in $S$
predicts failure with unchanged resources, location and craft bits, and
(iii) all profiles in $S$ predict the same observation. Prior evidence, rather
than search failure or shortage shared by the full family, causes rejection.
\begin{proposition}[Model-relative rejected action]\label{prop:reject}
Under true-profile inclusion and faithful transitions and observations, a
command satisfying (ii)--(iii) makes no modeled physical progress and does not
narrow $S$. It still costs one action. This alone does not establish that
deleting the command preserves the real game's future outcomes.
\end{proposition}
\begin{proof}
The true profile is quantified in (ii), so its physical projection is unchanged.
The same observation occurs for every survivor, so Equation~\ref{eq:update}
removes none. Elapsed time and remaining budget nevertheless change.
\end{proof}
\begin{proposition}[Conditional deletion with temporal assumptions]\label{prop:delete}
Additionally suppose the physical projection is a sufficient Markov state for
future projected transitions, observations, constraints and goal truth, all
independent of elapsed time. A policy starting with the rejected command and
having a verified suffix can omit that command and reach the same projected
endpoints under every profile using one fewer action.
\end{proposition}
\begin{proof}
The first command has one predicted observation and leaves the sufficient state
unchanged. Execute its unique suffix immediately. Induction over that suffix
gives identical subsequent projected states and observations under each profile.
Sufficiency preserves constraints and goal truth; deleting the unit cost enlarges
the available horizon by one.
\end{proof}
These temporal premises are not established for the games. A failed command can
advance time into a useful bonus or unlock. V11 adds calendar/hour cells, public
level/attack/defense and explicit modifier lines to the guard. This prevents
some transfers but proves neither invariance within an hour nor universal
safety. Game rejection is a model-relative decision rule evaluated by separate
shadow checks, not a certified full-game dominance rule.

\subsection{Necessary enabling conditions without fictitious completion}
For each surviving profile $\theta$, let $d_{i\theta}$ be the required amount
of ingredient $i$, $a_{i\theta}$ its accessible amount, $t_i$ its total in the
fragment, and $c_\theta$ the accessible storage capacity after fixed background
loads. Define
\[
 \delta_{i\theta}=\max(0,d_{i\theta}-a_{i\theta}),\quad
 \mu_{i\theta}=\max(0,d_{i\theta}-t_i),\quad
 \gamma_\theta=\max(0,\textstyle\sum_i d_{i\theta}-c_\theta).
\]
Set $c_\theta=\infty$ when the floor is accessible. Retain joint quantity/access
profiles: marginal minima must not be combined into a nonexistent favorable rule.
\begin{proposition}[Arrangement obstruction]\label{prop:obstruction}
In the fixed-recipe fragment without upstream production, outside supply,
attachment change or capacity change, assume exact unit-load capacities.
If for every $\theta\in S$ either some $\mu_{i\theta}>0$ or
$\gamma_\theta>0$, no rearrangement enables this craft in any survivor.
\end{proposition}
\begin{proof}
Rearrangement conserves each $t_i$, so it cannot repair a missing total.
Immediately before crafting all inputs must occupy accessible stores, and their
summed load cannot exceed those stores' capacity. One necessary condition fails
for each profile separately. These conditions need not be sufficient when they
hold: placement, transfer granularity and other preconditions can still block.
\end{proof}
A demonstrated lower capacity bound cannot justify the capacity obstruction.
Implementation requires matching observed bounds for that part of the test.
Supply obstruction concerns only this fragment. An obstruction asks the LLM to
seek an evidenced enabling change or another method; it is neither global
impossibility nor a new success exemption.

When rearrangement is not ruled out, V11 may run bounded repair search with
\emph{strong} success required for every survivor. A verified policy follows
actual feedback and is checkpointed; no exemptions are introduced. If none is
verified, explicit missing conditions accompany one bounded LLM revision;
search exhaustion remains unknown. Local-policy correctness follows the replay
argument of Theorem~\ref{thm:local} with no exemptions. No result here guarantees
that an arbitrary LLM replacement advances the whole quest.

\paragraph{Carried containers and observation prerequisites.}
A later implementation revision admits one fixed carried container. Its own
load is charged to the hand background; the container is excluded from movable
items and may not be a recipe operand or target. Actual feedback must preserve
its held count, or the certificate is revoked. This extends the supported
fragment without pretending that a dropped bag remains attached. Stale contents
require a charged inspection before grounding. That prerequisite is not labeled
a certified value-positive experiment: the needed query does not yet exist.
The revision was made after the full-game runs, and is not credited with their
scores.

\section{Task-anchored substitution and preservation of material options}
\label{sec:substitution}
The original public task $G$ must remain distinct from the output $y$ of a
proposed method. A recipe is evidence for a production relation, not for
$\operatorname{has}(y)\Rightarrow G$. In particular, a game task may say
``equip a weapon'' while its public completion signal occurs on picking up a
weapon; the command \texttt{equip} can still reject that same object. Neither a
successful craft nor a failed equip command alone determines the task binding.

\begin{definition}[Task bridge and provisional route]
A task bridge is a stated implication $g_j(x)\Rightarrow G(x)$ under an explicit
assumption set $\Gamma_j$. The assumptions include the correctness of the task
interpretation and all unexpressed task conditions. A provisional route is a
publicly observed recipe or dependency chain with an intended endpoint $g_j$;
it is not a task bridge and need not be executable. An observed category
description supports a role hypothesis, not the entire bridge. An actual public
completion report establishes completion of that particular encounter; reuse
of its interpretation requires a separate invariance assumption.
\end{definition}

The implemented V12 gate selects an exact pending task quotation, checks narrow
explicit output literals or public category descriptions, and follows bounded
numeric recipe dependencies. Unsupported interpretations remain unknown.
It does not infer an object's type from a suggestive name. An upstream ingredient
is relevant only via an evidenced dependency to a supported endpoint. This is
a necessary-role check, not a general natural-language entailment solver.

\begin{definition}[Material-option certificate]
Let $z\in\mathbb{R}_{\geq0}^d$ be the observed same-site material vector. Let
$\mathcal R=\{r_j\}_{j\in J}$ contain material requirement vectors for provisional
routes to the same task. Define
\[
 P(z)=\{j\in J:r_j\leq z\},\qquad
 z'_\theta=z-c_\theta(a)+p_\theta(a).
\]
Here inequalities are componentwise; $c_\theta$ and $p_\theta$ are consumption
and production under one retained effect profile. A conservative preservation
check requires $P(z)\ne\varnothing$, nonnegative intermediate material totals,
and
\[
 \forall\theta\in\Theta:\quad P(z)\cap P(z'_\theta)\ne\varnothing.       \tag{MO}
\]
New task-linked routes can replace the old portfolio, but their remaining
requirements must be checked jointly with other retained task commitments.
They are not justified merely by passing (MO).
\end{definition}

\begin{proposition}[What the reserve check certifies]
\label{prop:material-options}
Suppose $z$ and the listed effects are faithful, and the real effect profile
belongs to $\Theta$. If (MO) holds, at least one previously stocked route
remains stocked after $a$. Checking (MO) costs $O(|\Theta||J|d)$ and requires
neither full game-state enumeration nor a sum of all alternative routes'
ingredient demands.
\end{proposition}
\begin{proof}
Apply (MO) to the actual profile $\theta^*$. A member of
$P(z)\cap P(z'_{\theta^*})$ has its complete listed requirement vector available
both before and after the action. Enumerating the profiles, routes and vector
components gives the stated running time. Requiring the sum of all $r_j$ would
incorrectly demand simultaneous construction of mutually substitutable methods.
\end{proof}

This result is only about material availability. The quantifier order
$\forall\theta\exists j$ does not give an observation-based policy that knows
which $j$ to use. Capacity, attachment, navigation, observation costs and task
semantics may still prevent completion. If $P(z)$ was empty, an increased deficit
is a warning about the provisional route, not proof that a feasible task was
destroyed. Remote remembered stock and stale container contents do not enter
the implemented same-site certificate.

For multiple retained tasks, V12 also constructs a bounded relaxed production
schedule. It subtracts inputs from one shared material ledger, uses the largest
supported rounded ingredient requirement, and recursively obtains prerequisites
before appending the corresponding production operation. Cycles, missing leaves
and the expansion limit return no witness. Each distinct endpoint is reserved
once in this explicitly listed commitment set; the adapter does not claim to
extract every commitment from arbitrary task language.

\begin{proposition}[Joint material witness]
If the recursive construction returns a schedule with no missing leaf, then
that schedule supplies the listed endpoints in the material relaxation, under
each supported consumption rule, provided the observed recipes and their
production quantities are faithful. An unsuccessful construction does not prove
material infeasibility.
\end{proposition}
\begin{proof}
Induct over the returned schedule. Before appending a production, recursive calls
reserve its inputs from the shared ledger, expanding prerequisites if necessary.
No input is spent twice. The maximum rounded requirement upper-bounds each
supported rule, so executing any such rule leaves at least the reserved
remainder. Subtracting already available outputs and accounting for newly
produced outputs establishes the endpoint reservations. A cycle or expansion
cutoff can miss a usable alternative order, hence failure is inconclusive.
\end{proof}

\begin{theorem}[Conditional task-preserving substitution]
\label{thm:task-substitution}
Let a verification or substitution prefix $\nu$ have observation leaves $\ell$.
For every reachable leaf, suppose one common observation-based continuation
$\pi_\ell$ has been verified for every surviving profile to establish an endpoint
$g_{j(\ell)}$, preserve all modeled remaining obligations $K$, and use at most
$B-\cost(\nu,\ell)$ further actions. If the corresponding task bridges hold,
the actual model remains represented, and transitions and observations are
faithful, then the concatenated policy completes $G$ within $B$ and preserves
$K$ in the model.
\end{theorem}
\begin{proof}
The actual prefix follows one represented observation leaf. At that leaf its
model is included in the continuation's verification set. Applying the verified
continuation establishes $g_{j(\ell)}$ and $K$; the task bridge then yields $G$.
Adding the prefix and continuation action costs gives the budget claim. Different
hidden profiles with the same observed leaf cannot select different uncertified
continuations, which rules out an oracle-dependent choice of route.
\end{proof}

\paragraph{Implementation boundary.}
Theorem~\ref{thm:task-substitution} states sufficient conditions, not a guarantee
provided by every V12 repair. The implementation supplies the task-role audit,
material check, explicit unknown states and charged feedback loop. Its inherited
strong local planner verifies only its supported craft-and-hold fragment.
Recovering a previously equipped container across rooms is an observed-route
proposal, not a certified survival policy. An unsupported method substitution
is blocked before consumption; an evidenced same-task alternative can release
the old ingredients. A supported alternative with no joint material witness is
not admitted by this gate. Every final task claim still requires public task
feedback. This connects the new computation to the theory without pretending
that a recipe ledger solves the whole quest.

\section{Algorithm and correspondence with implementation}
\begin{enumerate}[label=\arabic*.,leftmargin=*]
\item Read public history and the remaining global budget. V6/LLM proposes the
method milestone; ground its supported fragment. On missing evidence, return
\texttt{GROUNDING\_UNKNOWN} without pretending that a trial was certified.
\item Compute the context and read its current raw-profile survivors. Compile
fresh quantities, resource constraints and observations using the surviving
\emph{joint} profiles; retain all behavioral aliases. Abort on compilation limits.
\item Fix the original goal-required profiles. Find and replay a common reference
policy if possible. Enumerate bounded first-split prefixes; require one verified
common continuation per leaf and the horizon/allowance tests.
V11 additionally rejects profile regret against a verified reference and
records whether reference-relative value is certified or unknown.
\item Execute the selected command; charge its action immediately. Match fresh
public feedback to predicted branches. On mismatch/gap, revoke the epoch and
cancel continuation. Do not reinterpret these events as task completion.
\item On a matched transition, lift surviving aliases and update the ledger
immediately, before the whole local trial completes. Follow its certified
observation branch without a new LLM call when possible.
\item At later queries, apply this ledger before search. Re-ground state and
re-verify a new policy. Never transplant an old plan solely because its evidence
context matches. Preserve global action expenditure across all queries.
\item Review later craft proposals even after the main search quota expires.
Use applicable evidence to expose enabling conditions. On a rejected proposal,
try a bounded strong local repair if not obstructed; otherwise request one LLM
revision. Charge every executed replacement and check its real outcome.
\end{enumerate}

\paragraph{Implemented.}
\texttt{resource\_competition.py} defines the finite semantics, constraints,
paired-profile filter and bounded experiment selector.
\texttt{resource\_trial.py} grounds one recipe at the current observed station
and follows actual feedback.
\texttt{resource\_evidence.py} implements guard/epoch ledgers and alias lifting.
\texttt{resource\_agent.py} retains V8, checkpointed V9 persistence and V10
cheap action review. V9 adds no evidence prompt; V10 adds bounded LLM revision.
\texttt{evidence\_repair.py} implements V11 passive craft observation, narrower
public context guards, necessary enabling conditions and strong local repair.
Its four evidence-use modes are none, prompt-only, exact contextual failure
cache and structured repair. They share the prospective gate and observation
collection; naturally diverging trajectories need not acquire identical facts.
Limits are six initial searches, at most six additional repair attempts,
a six-action local horizon and a 300-action global development budget.

\paragraph{Conditional properties.}
Theorems~\ref{thm:local} and~\ref{thm:reuse} require realizability, faithful
observations and adequate guards. Proposition~\ref{prop:budget} applies to
modeled action counts. Proposition~\ref{prop:monotone} concerns an exact optimum,
not bounded-search wall time. Proposition~\ref{prop:amortize} requires specified
future matched queries and pathwise costs; it is not an implemented scheduler.
Propositions~\ref{prop:profilevalue}, \ref{prop:reject} and
\ref{prop:obstruction} correspond to V11 checks. Proposition~\ref{prop:delete}
requires temporal sufficiency not established for the games.

\paragraph{Not implemented or not established.}
Automatic upstream/cross-location grounding, automatic guard discovery,
time-dependent rule inference, multi-recipe persistent correlations, full-quest
safety/completion, a learned estimate of future reuse value, and independent
full-game benefit of persistent evidence remain open. Generic route/upstream
support in the finite domain does not establish their automatic game grounding.
LLM-plus-planner composition and safe action-model learning have prior
precedents~\cite{dagan2023,juba2021,mehta2011}; the above correctness results do
not establish independent originality.

\section{Relationship to existing mechanisms}
Feedback-based revision is already central to AdaPlanner~\cite{adaplanner};
Reflexion~\cite{reflexion} stores verbal feedback in episodic memory, and
Voyager~\cite{voyager} combines iterative feedback with reusable executable
skills. Consequently, remembering failures, revising plans or reusing experience
is not our independent novelty claim. Safe lifted action-model
learning~\cite{juba2021} already establishes correctness under formal action-model
assumptions. Our present finite-family elimination is not a replacement for its
lifted-learning guarantees.

The narrower proposed contribution is a checked interface from uncertain joint
resource rules to budgeted local tests, scoped exclusion and explicit enabling
conditions in LLM execution. Establishing its importance requires advantages
over prompt-only evidence and contextual failure caching, not only an ablation
against forgetting. The four V11 arms are internal mechanism controls, not
faithful reproductions of Reflexion, AdaPlanner or Voyager. The elementary
correctness propositions do not by themselves establish an original planning
algorithm or empirical superiority over these systems.

\section{Validation and current evidential limits}
The new tests check correlated-pair filtering, alias lifting when batch sizes
change, count changes versus guarded context changes, mismatch revocation,
rejection of search results as evidence, checkpoint replay, and integration with
matched prompts. Existing tests cover destructive probes, paid hidden-container
observations, frozen exemptions, UNKNOWN retention and exact small-model oracles.

The zero-API audit in \texttt{audit\_persistent\_evidence.py} separates two kinds
of evidence. Two constructed bag-access instances (hand capacities one and two)
produce a verified three-action later plan without reuse and a two-action later
plan with correctly acquired accessible-bag evidence. The acquisition experiment
has worst cost four and explicitly uses allowance one; that extra allowance is
not enabled in the full-game configuration. These are mechanism examples with
modeled observations, not independent game episodes or an amortization result.

The chronological replay of all 11 grounded queries from the completed V8 game
runs feeds only earlier actual public feedback into each ledger. It produces
\textbf{zero reused later queries and zero changed decisions}. Subsequent
same-recipe contexts differ in attachment/equipment, other recipes are not
repeated, and some evidence is revoked after feedback gaps. Filtered-policy
outputs are offline counterfactual queries; historical outcomes are never claimed
to result from their actions. This negative result rules out attributing those
completed game scores to persistent evidence.

A later audit included actor proposals after the six-search quota, finding a
recurring Metropolis gavel context missed by that earlier selected-query audit.
A real-engine frozen-proposal replay spends one acquisition action in both arms
and then prevents three failures: 67 versus 64 actions, with equal final visible
inventory/location/equipment and quest score. Clock time differs, so hidden
state or future-outcome equivalence is not claimed. A separate V10 continuation
from after the shared acquisition reaches score 17 versus 16 at absolute step
300; neither completes the game. Repeated gavel failures fall from 11 to one;
all nine rejected proposals fail in separate real-engine shadow checks. Full
budget API requests rise from 139 to 161. One selected development scenario
and one sample per arm do not establish stable superiority or optimal test
selection. These data demonstrate persistent use of evidence, not the uniform
matched-query assumptions of Proposition~\ref{prop:amortize}.

The frozen V11 protocol evaluates four arms on fresh unseeded initial draws of
the three existing game templates. These are prospective trajectories, not new
independent game domains or formal repeated trials. Primary endpoints are quest
score and environment completion at the common action budget. Empty opportunity
sets, negative effects, model gaps, all acquisition costs, API use and latency
must be reported. Results are recorded separately from the source definitions;
no broad efficacy claim follows merely from implementing the four arms.

All twelve prospective runs reached the 300-action limit without environment
completion. Their primary quest scores were:

Mark & 13 & 16 & 13 & 13\\

The structured arm does not outperform these controls. It issued one
evidence rejection across the three games and no strong local repair
certificate; limited applicability prevents attributing most score differences
to the proposed mechanism. A chronological diagnostic found that clock cells
discarded useful cross-hour exclusions. A separately frozen, selected
Metropolis continuation tests attribute scoping without importing old
clock-scoped facts. It is exploratory development, not a second independent
validation set. Broader temporal scope remains an assumption to evaluate.
The continuation also ended at score 10: removing the clock cell did not improve
the primary score. An LLM repair crafted a gavel splint successfully and consumed
timber, but picking it up did not complete the intended weapon task. Its equip
attempt failed. This failure alone is not evidence that the item cannot serve
the task: later, picking up a gavel club completed that same task even though
the club's subsequent equip command also failed. The decisive issue is the
task binding and its public completion feedback, not equippability as inferred
from the natural-language task verb.

The carried-container revision was checked from the first eligible recorded
context without editing environment resources. One paid real inspection exposed
the current contents; the modeled fragment then lacked one required timber and
no verified continuation was returned. There was no new LLM call. This is a
useful abstention and a grounded diagnosis, not a positive task-completion result.
Tests separately verify the supported craft-and-hold policy and invalidate
container detachment. Constructive repair outside the fragment, and alignment
of alternative outputs with the original task, were unresolved in that revision.

The selected V12 repair starts before the previously observed unsupported
substitution. Replaying that frozen LLM proposal through the new gate rejects
the splint, retains timber, restores a previously observed inventory capability,
and then uses the public dependency executor. The actual weapon task completes
in 12 charged actions, versus 21 in the recorded V11 trajectory, with no new
LLM call in this native mechanism check. This is a selected development case.
The follow-on gate ablation uses the same continuation executor in every arm:
no gate takes 13 actions; the task-only, resource-only and joint gates each take
12. Thus most of the nine-action difference from the original trajectory is
attributable to the continuation executor. This case establishes only one
additional saved action from admission checking, with no incremental benefit
of the joint gate over either check alone. Unit counterexamples establish that
the checks are logically complementary; they do not establish empirical synergy.

On this public prefix, 100 repetitions of the review including task binding,
evidence scanning, dependency checks, quantity effects, joint material accounting
and JSON audit assembly have median time 0.731 ms and 95th percentile 0.780 ms
on the experiment server; the first call takes 1.720 ms. These measurements
exclude history reconstruction, acquisition search, engine actions and API
latency. They show low marginal check cost on this query, not a game speedup.
The final implementation also restricts historical loss-location inference:
a death following navigation cannot locate dropped objects at the departure
point. The final native replay still takes 12 actions, and 87 tests pass.

The live LLM continuation from step 93 completes the weapon task at step 108
instead of 114: 15 versus 21 actions from the common checkpoint, with 13 versus
21 new API requests up to that milestone. Both continuations finish at quest
score 10 at step 300. The new continuation uses 250 requests versus 263, but its
summed request latency is 701.8 versus 653.5 seconds; it is not an end-to-end
time improvement. It executes eight condition-restoration actions. The new
substitution gate itself is never invoked by an unsupported craft in this free
continuation; its gate-specific benefit is established only in the frozen
proposal check and the controlled continuation ablation.

clock scope, with the unchanged structured V11 runs as frozen controls:

Mark & 13 & 11\\

All six stop at the 300-action limit. The score sum is unchanged, and there is

changes, sampling and the previously native-only container support are
confounds; these score differences cannot validate the proposed gate. A late
trigger tied to a grounded failed craft has insufficient natural coverage.
The next mechanism question is maintaining the task binding at the point of
method selection, while distinguishing a valid upstream ingredient from an
unsupported goal substitution. Simply rerunning these baselines will not resolve
that question. This development round uses 1,181 new API requests with estimated
peak-price cost USD 2.43145 and no unknown-charge attempts. No unchanged baseline
is rerun. Paid trajectories retain their frozen source archive; the narrower
loss-location fix is tested separately with 87 tests and a native replay.

An exact thirty-configuration local matrix has zero grounding failures and
zero changed selected policies from the new profile-regret gate. Thus this
round establishes implementation and a stronger check, not extra selection
benefit in those configurations. Both gate settings compute the cost vectors,
so their measured times do not isolate overhead against legacy V10.
Four actual Mark queries do expose a strict distinction between the checks:
prefixes such as \emph{drop coal chunk; craft oak rod} have the same worst
cost three as the reference but lose one action under two retained profiles.
The pathwise gate rejects them. Replaying each query with the gate disabled
nevertheless selects the same final policy, because another candidate already
ranks ahead. Thus we have real-query evidence of a stronger rejection test,
but still no observed policy-selection or game benefit attributable to it.

The earlier V8 run scores were 2, 17 and 17 for Remnant, Mark and Metropolis;
Mark completed the environment. The frozen V6 scores were 3, 17 and 9. Those
runs motivate further game evaluation but have prompt/sampling differences and
are not a causal ablation of the new mechanism. No unchanged baseline was rerun.
The next efficacy test needs repeated applicable opportunities, matched initial
states and prompts, charged acquisition costs, and real quest outcomes. A smaller
candidate set, a cheaper local witness and improved full-game completion are
three distinct endpoints.
